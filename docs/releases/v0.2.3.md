# Grok plugin v0.2.3 — 사용자 릴리스 노트

**플러그인 버전:** `0.2.3`  
**이전 GitHub Release:** `v0.1.0` (초기)  
**대상:** Claude Code에 `grok` 플러그인을 설치해 쓰는 분

---

## 한 줄 요약

Claude가 **감독**, Grok이 **실행**, 당신은 **검수**하는 협업 루프가 갖춰진 **Grok starting point** 릴리스입니다.  
구독(SuperGrok / X Premium+) 과금 경로를 지키고, 위임 후 자동 커밋은 하지 않습니다.

---

## 설치 · 업데이트 (이용자)

Claude Code 안에서:

```
/plugin marketplace add xzawed/claude-grok-build-plugin
/plugin install grok@grok-marketplace
/reload-plugins
/grok:status
```

이미 설치했다면 마켓플레이스/플러그인 **업데이트 후 `/reload-plugins`**, 이어서 **`/grok:status`**로 `serverVersion`이 `0.2.3`인지 확인하세요.

사전 조건 (한 번):

1. Grok CLI 설치 + `grok login` (구독) 또는 API 모드 키  
2. 위임 후 **직접 커밋** (플러그인은 커밋하지 않음)

---

## 무엇이 좋아졌나 (v0.1.0 → v0.2.3)

### 안전한 위임 (과금 · 인증)

- **구독 기본**: 위임 시 API 키 env를 제거해 종량제 샌드를 막습니다.
- 응답마다 **`billing`** (`subscription` / `metered_api`) 표시.
- 미설치·미로그인 시 명확한 안내; 위임 전 **PreToolUse 인증 훅**.
- **`/grok:status`**: 준비 여부, 과금 기대값, 사용량, **`billingMismatch`**(구독 모드인데 과거에 종량제 이력이 있을 때 경고).

### 협업 루프 (Claude ↔ Grok)

| 단계 | 명령 / 도구 |
|------|-------------|
| 상태 | `/grok:status` |
| 누구에게 맡길지 | `/grok:route` → **`nextAction`** |
| 계획만 | `/grok:plan` |
| 실행 | `/grok:delegate` · `/grok:verify` |
| 검수 | `/grok:review` (자동 커밋 없음) |
| 이어서 | `/grok:resume` (이전 `sessionId`) |
| 사용량 | `/grok:usage` |

- 프리셋: `/grok:tests`, `/grok:migrate`, `/grok:boilerplate`
- 위험 작업: `worktree` 격리 + `/grok:worktree` list/diff/apply
- 첫 사용: `/grok:tour` · 문서 `docs/08-getting-started-with-grok.md`

### 안정성 · 플랫폼

- Windows에서도 CLI 탐지·핵심 위임 경로 동작 (설치는 PowerShell `install.ps1`).
- CI (Linux + Windows), PreToolUse 하네스 e2e, 번들 tool 목록 검증.

## 이용 시 꼭 알아둘 것

1. **자동 커밋/PR 없음** — diff 검토 후 직접 커밋하세요.  
2. **`billing: metered_api`가 보이면** — 셸의 `XAI_API_KEY`가 세션보다 우선일 수 있습니다. `/grok:status`의 `billingMismatch`를 확인하세요.  
3. **위험·큰 변경**은 `worktree: true` 권장.  
4. **보안·아키텍처·최종 리뷰**는 Claude/사람에게 남기세요 (`/grok:route`가 `claude`를 권하면 Grok에 억지로 맡기지 마세요).
