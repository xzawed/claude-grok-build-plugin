# v0.2.49 — grok이 이름을 바꾼 `worker`(옛 `cursor-worker`)도 띄우지 않는다 (A79)

2026-10-28. grok의 도움말은 `cursor-worker`를 `worker`로 바꿨다(1.0.52 도움말은 옛 이름, 1.0.67·1.0.70은 `worker`). 다만 1.0.70도
`cursor-worker`를 **숨은 별칭으로 여전히 받는다**(`grok cursor-worker --help`가 exit 0, 최상위 도움말에는 0번). 이 명령은 이 PC를 Cursor
private worker로 등록하는 leader를 띄우고 Ctrl+C까지 돈다 — 계정에 작용하고 호출보다 오래 산다. 래퍼의 거부 목록(A29)은 옛 이름만 쥐고
있어서, `grok_cli`가 두 모양에서 `grok worker start`를 띄웠다. 이제 두 이름 모두 spawn 없이 거부하고, 같은 부류의 숨은 서브커맨드
`workspace`("Expose this workspace to the Computer Hub")도 거부한다. 같은 릴리스가 grok 1.0.70의 표면을 다시 재고, 플래그 표에 없던 열
개를 넣었다.

## 재현 (쿼터 0 — grok 1.0.70, Linux 컨테이너 `--network none`)

grok 1.0.70과 번들을 네트워크 없는 컨테이너에 넣고, 빈 `GROK_HOME`(세션 없음)에서 `.claude/tools/mcpcall.mjs`로 번들을 띄웠다. v0.2.48은 이
PC에 설치된 캐시, v0.2.49는 이 릴리스의 번들이다.

| `grok_cli` 인자 | v0.2.48 | v0.2.49 |
|---|---|---|
| `["cursor-worker","--help"]` | `blocked` | `blocked` |
| `["worker","--help"]` | `ok`, exit 0 — worker 도움말 | `blocked` |
| `["worker","start"]` | `blocked`(프롬프트 규칙 — 첫 단어가 아는 서브커맨드가 아니다) | `blocked`(거부 목록) |
| `["--add-dir","sessions","cursor-worker","start"]` | `blocked` | `blocked` |
| `["--add-dir","sessions","worker","start"]` | **spawn** — 20초 상한까지 돌아 `timeout` | `blocked` |
| `["-p","hi","worker","start"]` | **spawn**(`promptRun: true`) — 20초 상한까지 돌아 `timeout` | `blocked` |
| `["leader","worker","start"]` | `blocked`(`leader`) | `blocked` |
| `["--harness","sessions","delta four"]` | **spawn** — exit 1, `No such device or address`(맨 프롬프트 `"delta four"`만 준 grok과 같은 오류 — 대화형 경로가 컨테이너에서 터미널을 못 열었다) | `blocked` |
| `["--add-dir","/tmp","sessions","list"]` · `["sessions","list"]` | `ok`, exit 0 | `ok`, exit 0 |

같은 컨테이너에서 grok을 직접 띄우면 `worker start`·`-p hi worker start`·`--add-dir sessions worker start` 모두 leader를 띄우고
(`leader.lock`) 부팅 때 Cursor worker를 시작하려다 설정이 없어 멈춘 채 신호를 받을 때까지 돌았다(grok 로그 — 계약 머리 "1.0.70 표면").
세션과 `--worker-dir`(또는 설정의 `[cursor_worker] worker_dirs`)이 있으면 이 PC를 Cursor에 등록하는 명령이다(grok 도움말) — 계정에
작용하므로 그 경우는 재지 않았다.

## 왜 빠져나갔나

- 거부 목록(`NON_HEADLESS`)은 낯선 플래그가 앞에 있어도 모든 위치를 훑어 막는다(A29). 그 목록에 새 이름이 없었다.
- 남은 방어는 프롬프트 규칙(A52)이었다 — 아는 서브커맨드가 아닌 첫 단어를 프롬프트로 보고 거부한다. 그 규칙은 프롬프트 플래그(`-p`)가
  있는 실행은 hook과 기록에 맡기고, 표에 없는 플래그 뒤에서는 아는 서브커맨드가 뒤따르면 물러난다. `-p hi worker start`는 앞의 경우이고
  (grok은 서브커맨드 앞의 최상위 `-p`를 무시하고 `worker start`를 돌렸다), `--add-dir sessions worker start`는 뒤의 경우다(`--add-dir`은
  1.0.50 뒤에 생겨 어느 표에도 없었고, grok에게는 그 값인 `sessions`가 아는 서브커맨드였다).

## 거부 목록의 위치 스캔도 함께 고쳤다 (Grok 반증이 연 것)

Grok 반증 1회차가 `["--header","-p","worker","start"]` 같은 모양을 짚었다. 거부 목록이 쓰는 `grokPositionals`는 `VALUE_FLAGS`만 알아서,
`--header`(이번에 표에 넣은 숨은 값 플래그)를 모르고 지나쳤고, 그 뒤의 `-p`(값 플래그)가 `worker`를 값으로 먹은 것으로 잘못 읽어 `worker`가
스캔에서 빠졌다. 실측해 보니 **grok 1.0.70은 이 모양을 exit 2로 거부한다** — clap은 `-`로 시작하는 토큰(`-p`)을 값 플래그의 값으로 받지 않는다
(그 사실을 "무엇이든 받는다"로 과장해 Grok에 준 것이 1회차 오탐의 원인이다). 그래서 worker가 실제로 돌지는 않았지만, 래퍼는 그래도 grok을
**띄웠다**(`status: "error"`). 고친 방향은 자동 보안 리뷰의 지적을 따랐다: **`grokPositionals`는 문서화된 `VALUE_FLAGS`만 믿는다** —
`HIDDEN_VALUE_FLAGS`는 넣지 않는다(이름이 `--help`에 없고 arity가 실측 추정이라, 어느 날 스위치로 바뀌면 스캔이 서브커맨드를 건너뛰어 fail
open이 된다). 숨은·모르는 플래그는 파스를 불확실하게 만들 뿐이고, 그러면 그 뒤로는 어떤 값 플래그도 다음 토큰을 먹지 않는다(모두 위치
인자로 훑는다 — "불확실하면 모든 위치를 훑는다"의 fail-closed 해석; `--print`와 미래의 모르는 플래그까지 덮는다). grok이 실제로 worker를 돌리는
모양(`--harness x worker start`, `--harness=-p worker start`, `--mode ask worker start`, `-p hi worker start`, `--add-dir sessions worker
start`, 그리고 `anyword --harness x worker start`)은 거부 목록이나 프롬프트 규칙(맨 단어 `anyword`)이 모두 막고 spawn하지 않는다 —
설치본 0.2.48(spawn)과 이 번들(차단)로, 그리고 grok이 그 모양에 worker leader를 띄우는 것(exit 124·leader 로그)으로 쟀다.

## 동작 변화

1. `worker`·`cursor-worker`·`workspace`는 grok이 worker/workspace로 **실제로 돌릴** 모양에서 spawn 없이 `blocked`다(낯선 플래그 뒤, 프롬프트
   뒤의 COMMAND 자리 포함). 메시지는 다른 비-헤드리스 명령과 같다("터미널에서 직접 실행하세요"). `worker status` 같은 읽기도 함께 막힌다 —
   분류는 최상위 서브커맨드로만 한다. (grok이 어차피 exit 2로 거부하는 모양 중 몇은 아래 "거부 목록의 위치 스캔"을 보라.)
2. 플래그 표에 열 개를 더했다(계약 머리 "1.0.70 표면"·§16): 도움말에 있는 값 플래그 `--add-dir`과 `--allow`의 별칭 `--allowed-tools`, 숨은 값
   플래그 `--background-shell-timeout`·`--conversation-history-file`·`--harness`·`--header`·`--mode`, 숨은 스위치 `--endless-retries`·
   `--exclude-workspace-context`·`--retry-all-inference-errors`. 프롬프트 규칙은 이제 이것들을 지나 읽는다. 전에는 이 플래그 뒤에 아는
   서브커맨드 이름이 오면 그것이 그 플래그의 값이어도 물러났다 — 위 표의 `--harness` 줄이 그 모양이고, A52 검토가 v0.2.41(win32, 1.0.44)에서
   맨 단어가 모델에 가는 것을 쟀던 모양이다(1.0.70의 이 열 개로는 모델 요청까지 재지 않았다).
3. `grok_cli` 도구 설명, README 두 판, `docs/03`·`docs/04`의 거부 목록이 `worker`를 댄다.

## 유지보수 (번들 밖)

- `probe:contract` 스냅샷을 1.0.70으로 갱신했다 — 분류를 마친 뒤.
- **probe가 숨은 서브커맨드를 본다.** `--help`는 숨은 서브커맨드를 안 적어서(`cursor-worker`·`workspace`), 서브커맨드 목록을 `--help`에서만
  뽑던 probe와 그걸 읽는 테스트는 그 둘을 아예 보지 못했다 — A79가 숨은 채 지나간 메커니즘이다. 이제 probe가 `grok completions bash`의
  `grok,<이름>)` 케이스에서 최상위 이름 전부(숨은 것·별칭 포함)를 뽑아 스냅샷(`completionsSubcommands`)에 두고 드리프트로 비교하며,
  `grok-cli.test.ts`가 그 목록의 모든 이름이 `KNOWN_SUBCOMMANDS`나 `NON_HEADLESS`에 있는지 본다(전엔 `--help` 목록만 봤다). 이 PR에서
  `workspace`로 실패하는 것을 봤다. 중첩된 숨은 명령은 아직 못 본다(계약 §16).
- 숨은 플래그 탐침의 후보를 넓혔다(후보 8,128개): 바이너리의 케밥 문자열과, 잇달아 적힌 `--a--b`를 나눈 이름. 1.0.50 때의 출처로는 열 개 중
  다섯을 놓쳤다. 열 개 모두 1.0.50 뒤에 생겼다(Linux 1.0.50은 하나도 받지 않았다) — 1.0.50의 기록은 그대로다.

## 검증

- 새 테스트는 고치기 전 소스에서 실패하고 고친 뒤 통과한다 — 두 이름과 `workspace`의 거부, 거부 목록 위치 스캔이 가리던 모양들
  (`grokPositionals`를 되돌리면 실패), 스냅샷의 서브커맨드(숨은 것 포함)·플래그 검사, 숨은 플래그 분류, 새 플래그 파싱. 수치는 `npm test`가
  원천이다 — 전체 통과(무거운 `redact-floor`·`worktree` diffStat 케이스가 win32 전체 병렬 부하에서 가끔 흔들려 그 파일만 격리 재실행해
  통과 확인했다; 회귀 아님 — 이 세션의 메모가 기록).
- 다시 잰 것: 위 표의 v0.2.49 열(같은 컨테이너, 이 릴리스의 번들). 마지막 줄(`--header "X: y" sessions list`)은 고친 뒤에도 `ok`로 돈다.
- Grok 반증(정적, effort low): 1회차는 CLAIM_BROKEN이었다 — 위 "거부 목록의 위치 스캔"의 모양들(오탐: 준 facts의 F3가 과장이었다). 그
  정렬을 고치고 facts의 F3를 clap 실측대로(“`-` 시작 토큰은 값으로 받지 않고 exit 2”) 바로잡아 2회차를 돌렸고, 11개 경로(P1–P11) 모두
  HOLDS다 — 래퍼가 통과시키는 모양은 모두 grok이 exit 2로 거부하고(`anyword --print x worker start`, `sessions worker start`를 직접
  실측), worker가 실제로 도는 모양은 모두 막힌다.

## 하지 않는 것

- `worker`를 `KNOWN_SUBCOMMANDS`에 넣지 않는다 — 계정에 작용하는 명령은 거부 목록이다(A29). 터미널에서 실행한다.
- `--header`로 `Authorization`을 실은 턴이 어떻게 과금되는지는 재지 않았다. 구독 모드의 env 정제(절대 원칙 1)는 인자를 보지 않는다.
- `--add-dir`로 grok이 다른 폴더를 고쳐도 `grok_cli`의 `filesChanged`는 grok을 띄운 폴더만 본다(코드 — 인자의 `--cwd`도 같다). 바꾸지 않았다.
