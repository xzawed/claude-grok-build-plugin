# v0.2.13 — 감사가 재현해낸 것들

2026-09-03. 전체 코드·문서 감사(31건 발견 → 항목별 3중 교차검증)의 결과를 반영한다.
살아남은 항목은 **전부** 실제 명령으로 재현했고, 가장 중대한 것들은 Grok이 독립적으로 다시
재현했다. 감사 방법과 전체 목록의 원천은 세션 감사 리포트(**Grok Plugin Audit Ledger** — 소유자 전용
아티팩트)이며, 그 결론은 이 문서와 `CHANGELOG.md`가 담는다. 아티팩트를 열 수 없는 독자를 위해
**반증된 4건은 아래 절에 옮겨 적었다** — 레포만 읽고도 자립하도록.

> **왜 0.2.12가 아니라 0.2.13인가.** `v0.2.12`는 매니페스트에 선언되고 main에 머지됐지만
> **태그도 GitHub 릴리스도 만들어지지 않았다**. 마켓플레이스 소스가 `./`이므로 그 사이에
> 설치한 사용자는 0.2.12로 캐시된 옛 번들을 갖는다. 캐시는 버전 키이므로 같은 번호로 다른
> 번들을 다시 내보내면 안 된다 — `CLAUDE.md`가 경고하는 바로 그 상황이라 범프했다.

## 사용자의 작업을 잃게 만들던 것 (3건, 각 3회 검증)

### `prune --apply`가 상태를 확인할 수 없는 트리를 지웠다

`dirty`는 상태 프로브가 실패하면 *의도적으로* `undefined`로 남는다("clean이라고 추측하느니
모른다고 두자"). 그런데 이를 읽는 두 곳 모두 `if (c.dirty)`였고 `undefined`는 falsy다 —
**"모름"이 곧 "지워도 됨"으로 읽혔다.** 더구나 프로브가 실패하는 조건(소유 repo 소실)이
`removeGrokWorktree`를 실패시켜 고아 `rmSync` 경로로 보내는 조건과 같다. 즉 둘은 항상 함께
왔다.

실측: 미적용 grok 산출물을 담은 고아 트리가 `ok:true`와 함께 삭제됐고, blob·reflog·브랜치
어디에도 남지 않았다. 이제 **확실히 clean인 트리만** 제거하고, dry run이 그 수를 세어
경고하며, 두 메시지 모두 "상태 불명"을 명시한다. 정상 GC 경로(상태가 답하고 clean인데 git이
제거 못 하는 고아)는 그대로 동작한다 — Grok이 과잉교정 아님을 확인했다.

### `apply`가 UTF-8이 아닌 텍스트 파일을 조용히 손상시켰다

패치가 bytes → JS 문자열 → bytes로 왕복하며 양끝이 `utf8`이었다. `--binary`는 git이 *binary로
분류한* 파일만 보호하므로, NUL이 없는 CP949·EUC-KR·Latin-1 텍스트는 그대로 망가져 사용자의
실제 워킹트리에 `ok:true`와 함께 쓰였다.

```
63 61 66 e9 0a  →  63 61 66 ef bf bd 0a
```

패치를 Buffer로 캡처하고 Buffer로 쓴다. 검증: 신규 Latin-1 · 기존 파일에 비-UTF-8 줄 추가 ·
실제 바이너리 · 한글 UTF-8 전부 바이트 동일.

### `apply`에 경로 봉쇄가 없었고, 실패하기 전에 대상을 파괴했다

`remove`·`prune`은 `isPathInsideBase`로 막지만 `apply`는 절대경로 검사뿐이었다. 그리고
`add -A`·`reset HEAD -- .`이 중단시킬 수 있는 `apply --check`보다 **먼저** 실행됐다. 일반
저장소를 가리키면 적용이 아무것도 못 해도 그 저장소의 staged index가 비워졌고, 실패 메시지는
그 사실을 말하지 않았다. 이제 `remove`와 같은 봉쇄를 적용한다.

## 조용한 오보고 (3건)

- **하위 디렉토리 `cwd`에서 apply가 변경을 누락**했다. worktree는 저장소 **루트**를 체크아웃하므로
  패치가 루트 상대인데 `git -C <subdir> apply`로 재생하면 git이 바깥 항목을 조용히 무시한다 —
  exit 0에 `--check`까지 통과해 fail-closed 게이트가 무력했고, `filesChanged`는 누락된 파일을
  적용했다고 보고했다. 이제 toplevel을 해석해 거기서 적용한다.
- **`filesChanged`가 untracked 디렉토리 안의 파일을 전부 숨겼다.** `-uall`이 없으면 git이
  디렉토리를 한 항목으로 접는다. 그 항목이 before 스냅샷에도 있으면 before/after가 동일해져
  파일을 쓰고도 `[]`가 나온다. 이 플러그인은 커밋하지 않으므로 그 디렉토리는 계속 untracked로
  남아 **이후 모든 위임이 "변경 없음"을 보고**했다. `delegate.ts`·`worktree.ts` 양쪽에 `-uall` —
  `worktree diff`와 `worktree apply`가 같은 트리를 두고 서로 다른 답을 내던 것도 함께 사라진다.
- **`diffStat`이 staged·untracked에 눈이 멀었다.** 맨 `git diff --stat`은 워킹트리와 index만
  비교한다. `--always-approve` grok은 새 파일을 만드는 일이 잦아, 흔한 경우가 "파일 목록은 가득
  찬 채 stat은 비어 있음"이었다. `git diff HEAD --stat`도 똑같이 읽기 전용이다.

## 그 밖

- **`-`로 시작하는 프롬프트가 모델에 도달조차 못 했다.** bare option value로 넘기면 clap이
  거부한다(exit 2, stdout 없음, 모델 호출 없음) — 래퍼는 이를 "grok 출력을 해석할 수 없음"으로
  보고했다. 실측: `-p "- Refactor"` exit 2, `"--single=- Refactor"` exit 0이며 일반·다중행·따옴표
  프롬프트에서도 동일. `--single=` 형태로 바꿨다.
- **grok 설치 프로브가 `src/`의 유일한 무제한 spawn**이었고 모든 게이트 호출 앞에서 돈다.
  `where.exe`는 매치 후에도 PATH 전체를 훑으므로 도달 불가 UNC/매핑 드라이브 항목 하나가
  약 21초씩 멈춰 세웠다. 타임아웃·maxBuffer를 붙였다.
- **bulk 휴리스틱이 일반 문장에 오탐**했다. `n files`가 앵커 없는 부분 문자열이라
  "i**n files**"·"broke**n files**"에 걸리고 `every `가 "on every request"에 걸려, 평범한 디버깅
  작업이 LOW/grok/무인 위임으로 갔다 — 이 모듈이 스스로 내건 fail-closed 원칙의 역이다. 이제
  실제 숫자 카운트와, 시간이 아니라 작업을 뜻하는 명사 앞의 `every`만 본다. 덤으로 예전 패턴이
  아예 놓치던 "update 40 files"가 이제 잡힌다.

## 문서 — 부작용을 숨기던 커맨드

- **`/grok:trace`는 기본이 원격 업로드**다(`--local`이 opt-out). 문서는 `--local`도, 필수
  `<SESSION_ID>`도 언급하지 않았고, 없는 "subcommand"를 쓰라고 지시했다. 세션(프롬프트·파일
  내용·툴 트레이스)을 기본으로 외부에 보내는 유일한 커맨드이면서 그 사실을 안 적은 유일한
  문서였다. 이제 `--local`을 기본으로 안내하고 업로드는 명시적 요청에만.
- **`/grok:update`는 기본이 설치**다(`--check`가 opt-in). "새 버전 있어?"가 바이너리 교체가
  되지 않도록 `--check --json`을 기본 경로로 바꾸고, 설치 시 타임아웃 상향을 안내한다.
- **`/grok:memory`** 는 `clear -y`가 `MEMORY.md`만이 아니라 `sessions/`·`index.sqlite`까지
  지운다는 것을 명시한다.

## 반증된 것도 남긴다

감사가 올린 31건 중 12건이 반증 렌즈를 통과했고, 그 렌즈가 **4건을 죽였다.** 죽은 것을 남기는
이유는 "찾아봤다"와 "찾았는데 없었다"가 다르기 때문이다 — 아래 근거를 반박하지 못하면 다시
제기하지 않는다.

| 반증된 주장 | 왜 결함이 아닌가 |
|---|---|
| git 실패가 `filesChanged`를 `[]`로 무너뜨린다 | `[]`는 repo가 아닌 cwd에 대한 **공표된 계약**이다. 탈출구(`worktree: true`)는 시끄럽게 fail-closed로 끝나고, `summary`는 빈 목록 옆에 grok 자신의 보고를 항상 함께 싣는다. probe 비용은 10초 상한 대비 **147 ms**로 측정됐다. |
| 구독 모드에서 설치 probe가 중복 실행된다 | 실재하지만 **플러그인이 배포하는 어떤 것도 `GROK_BUILD_AUTH_MODE`를 설정하지 않는다.** 일반 사용자는 `unknown` 경로로 가서 probe를 정확히 한 번 친다. 지연 차이는 프로세스 노이즈 안이었다. |
| hook과 서버의 모드 불일치가 오차단을 만든다 | 한 변수에 **서로 모순되는 두 값**을 준 경우에만 발생한다. 문서가 "hook에게 보이지 않는다"고 부른 구성은 실측에서 `allow`였다. 모호한 표기는 전부 fail-open. |
| 명시적 `security: false`가 키워드로 추론된 HIGH를 덮는다 | 버그가 아니라 **명세된 우선순위**다 — signals는 키워드보다 권위 있다고 정의돼 있고, 뒤집으면 키워드 오탐을 사용자가 고칠 방법이 없어진다. 게다가 `routeTask`는 아무것도 게이트하지 않는다. |
