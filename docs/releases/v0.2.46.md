# v0.2.46 — a resume of a long-cwd (>255 byte) session reports the real cwd, not grok's slug-hash dir name (A69)

2026-10-23. A69는 2026-10-14에 Grok의 판단대로 먼저 재서 연 결함이다(계약 §12). grok은 url-인코딩한 cwd가
255바이트를 넘으면 세션 폴더를 `<slug>-<16자리 hex>`로 짓고 실제 cwd를 그 폴더의 `.cwd`(UTF-8)에 둔다. 래퍼의
`resolveSessionCwd`는 폴더 이름을 `decodeURIComponent`로만 풀어, 그런 세션을 resume하면 slug-해시를 cwd로 말하고
"그 디렉터리에서 작업했습니다"라 거짓 안내했다 — 귀속용 git 조회와 continue 위치 안내도 같은 함수를 쓴다. 한글 같은
비 ASCII 이름(한 글자 9바이트)이나 Linux·macOS의 깊은 경로는 이 한계에 쉽게 닿는다.

| | 사용자에게 보이던 것 | 이제 |
|---|---|---|
| resume·continue의 `resumedCwd`와 위치 안내 (A69) | 인코딩 255바이트 초과 세션을 resume하면 `resumedCwd: "aaaa-4d506a2863e2f73d"`(폴더 이름)와 "resume한 세션은 aaaa-...에 속해 있어 ... 그 디렉터리에서 작업했습니다" — slug-해시를 cwd로 단정했다. 귀속용 git 조회도 그 상대 이름을 폴더로 삼았다 | 폴더 이름이 절대 경로로 풀리지 않으면(slug-해시) 그 폴더의 `.cwd`를 읽어 **실제 cwd**를 말하고, 읽을 수 없으면(없음·비정규 파일·크기 초과·비절대) **아무 말도 하지 않는다** — slug는 절대 말하지 않는다. 세션 자신의 cwd로 resume하면 "다른 폴더" 경고가 사라진다 |

## 재현 (쿼터 0 — grok은 미인증으로 즉시 끝난다)

배포 번들을 `.mcp.json`처럼 stdio로 띄워, 격리 `GROK_HOME`에 `sessions/aaaa-4d506a2863e2f73d/<id>/`와 그 폴더의
`.cwd`(절대 cwd)를 두고 resume했다. `{}` auth.json이라 delegate는 인증 게이트를 통과해 진행하고 grok은 미인증으로
~3초 만에 `auth_error`로 끝나지만, 래퍼는 spawn 전에 `resolveSessionCwd`로 `resumedCwd`를 계산해 응답에 붙인다.

- 전(v0.2.45): `resumedCwd: "aaaa-4d506a2863e2f73d"`, 메시지 "...그 디렉터리에서 작업했습니다"(거짓).
- 후, 세션 자신의 cwd로 resume: `resumedCwd` 없음, "다른 폴더" 주장 없음.
- 후, 다른 cwd로 resume: `resumedCwd`가 `.cwd`의 실제 경로, 메시지도 그것을 가리킨다 — slug는 나오지 않는다.

## 고친 방법

- `mcp-server/src/delegate.ts` `resolveSessionCwd`: 폴더 이름을 디코딩해 **절대 경로면 그대로**(정상 세션, 동작
  불변), 아니면 `index.readLongNameCwd?.(dir)`로 `.cwd`를 읽는다.
- `SessionsIndex`에 `readLongNameCwd?`(옵션)를 더하고 `defaultSessionsIndex`에 배선. `readLongNameCwdFile`은
  `.cwd`를 **정규 파일 · 8192바이트 상한 · 절대 경로 · 끝 개행 제거**로 읽고, 어떤 예외도 `undefined`로 떨어진다 —
  grok이 소유한 레이아웃이라 "틀린 주장보다 무주장"(계약 §12).
- `resumeOwner` · 귀속용 git before 스냅샷 · continue 위치가 모두 `resolveSessionCwd`에서 파생되므로, 이 한 함수
  수정이 셋을 모두 고친다.

## Grok과 함께

- 반증(5단계): 수정 diff와 고친 `delegate.ts`를 빈 폴더에 그대로 떼어 다섯 검사(slug 누출 · 정상 경로 불변 ·
  `.cwd` 읽기 안전 · 하위 경로 귀결 · 플랫폼)를 정적 분석시켰다 — `VERDICT: FIX_SOUND`, 모두 "none". readdir 항목은
  경로 구분자를 담을 수 없어 slug가 절대 경로로 보일 수 없다는 점, `lstatSync`가 심링크 `.cwd`를 비정규 파일로 걸러
  무주장이 되는 점, win32 이름이 POSIX에서 보여도 `.cwd`가 없으면 slug가 아니라 무주장이 되는 점까지 확인했다.
