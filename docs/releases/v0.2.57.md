# v0.2.57 — xAI가 결제·사용량으로 거절한 턴(HTTP 402)을 알아보고 무엇인지 말한다 (`docs/09` §4 J, 2차 순서 3번)

2026-11-29.

구독의 Grok Build 사용량이 소진되면 xAI는 그 턴을 HTTP 402로 거절한다. 2026-11-04에 위임 넷이 그렇게 끝났다(grok 1.0.70, v0.2.51
번들). 그때 래퍼는 grok의 원문 "Internal error: { … API error (status 402 Payment Required): Grok Build usage balance exhausted … }"를
`grok_error`로 그대로 넘겼다. 다시 해도 같다는 말도, 종량제로 넘어가지 않았다는 말도 없었다(`docs/09` §4 J).

2026-11-05 오너가 "알아보고 안내"를 골랐다. 2026-11-29 남은 작업의 2차 순서에서 이 릴리스가 3번이 됐고, routing 스킬 한 줄이 함께 간다.

## 재현 (쿼터 0 — grok 1.0.92, win32, 실제 `~/.grok` 미접촉)

**조건.** 버릴 홈의 합성 세션을 썼고, grok의 API 주소 둘을 루프백으로 돌렸다(계약 §17).
- 루프백은 주 턴(`POST /v1/responses`)만 402로 답하고 나머지는 404로 답했다.
- 402 본문은 네 가지다:
  - `{"error":"Grok Build usage balance exhausted"}` — 2026-11-04에 xAI가 보낸 줄을 글자까지 재현한다;
  - `code`를 곁들인 것;
  - `error`를 객체로 둔 것;
  - JSON이 아닌 것.
- 대조는 모두 404로 답한 경우다.

**번들 구동.** `.claude/tools/mcpcall.mjs`로 띄우되 env를 격리했다.
- 이 셸의 GROK_*·XAI_* 변수를 모두 뺐다.
- 홈 넷과 `CLAUDE_CONFIG_DIR`을 버릴 폴더로 돌렸다.
- api 모드의 키는 가짜이고 루프백으로만 갔다.

v0.2.56 열은 그날 `main`의 번들, v0.2.57 열은 이 릴리스의 번들이다.

| 경우 | v0.2.56 | v0.2.57 |
|---|---|---|
| 위임·plan·verify, 구독, xAI의 말 | `grok_error`, `message`는 grok 원문 "Internal error: {…}" | `grok_error`, `paymentRequired: true`, "구독의 Grok Build 사용량이 소진됐습니다(xAI의 HTTP 402 — "Grok Build usage balance exhausted"). 사용량이 돌아올 때까지 다시 시도해도 같습니다. 종량제로 넘어가지 않았습니다 — 구독 모드는 env의 API 키를 grok에 넘기지 않습니다." |
| 위임, 구독, `code`를 곁들인 본문 | 원문 | 같은 안내(따옴표 안은 `Payment Required: Grok Build usage balance exhausted`) |
| 위임, 구독, JSON이 아닌 본문 | 원문(grok의 말 "Request failed (HTTP 402).") | `paymentRequired: true`, "xAI가 이 요청을 HTTP 402(Payment Required)로 거절했습니다 — …" — 사용량 소진이라고 하지 않는다 |
| `grok_cli ["-p","Say ok."]`, 구독 | `error`, exit 1, `message` 없음 | `error`, exit 1, `paymentRequired: true`, 위와 같은 안내 |
| 위임·`grok_cli`, api 모드(가짜 키) | 원문 / `message` 없음 | `paymentRequired: true`, 구독 사용량 소진도 "종량제가 아니다"도 말하지 않는 안내 |
| 404 대조(위임·`grok_cli`) | 원문 / `message` 없음 | 같다 |

경우마다 모델 요청 셋이 402를 받았다(모두 `POST /v1/responses`). 위임 쪽의 `rawStderrTail`·`sessionId`와 `grok_cli`의 출력은 두
판이 같다. 하네스가 남긴 프로세스는 0이다.

## 고친 것

- **`delegate.ts`의 `paymentRequiredReason`.** grok 자신의 줄 `API error (status 402 …): <말>`이나 `"http_status": 402`를 찾아,
  그 안의 xAI의 말을 돌려준다. 읽는 곳은 실패한 실행의 오류 봉투 문장과 stderr뿐이고, 성공한 실행의 요약은 읽지 않는다.
- **`paymentRequiredMessage(mode, 말)`.**
  - 구독 모드: xAI의 말이 사용량 소진이면 "구독의 Grok Build 사용량이 소진됐습니다…"이고, 아니면 "HTTP 402로 거절했습니다…"이다.
    끝에는 "종량제로 넘어가지 않았습니다 — 구독 모드는 env의 API 키를 grok에 넘기지 않습니다."가 붙는다.
  - api 모드: 거절 문장과, 그 요청이 쓴 자격증명(구독 세션이나 API 키)을 확인하라는 말만 한다. 어느 쪽을 썼는지 래퍼는 모르기
    때문에(계약 §10), 구독 사용량이 소진됐다고도 종량제가 아니라고도 말하지 않는다.
- **위임·plan·verify(`classifySpawnResult`).** 실패한 갈래 넷에서 인증 판단 바로 뒤에 묻는다.
  - 오류 봉투 갈래: 봉투 문장과 stderr를 본다.
  - 봉투 없는 갈래: stderr를 본다.
  - 계획 텍스트가 빈 plan: stderr를 본다. Grok 반증이 찾은 빈틈이다.
  - 봉투는 읽혔지만 `stopReason`이 성공이 아닌 위임·verify: stderr만 본다. 그 갈래의 인증 판단과 같다.
  - 뒤의 두 모양은 재지 않았다. 잰 402는 오류 봉투였고, 거기서는 grok 자신의 줄이 증거다.
  - 텍스트를 돌려준 plan은 설계대로 완료이니 그대로다.
  - `status`는 `grok_error` 그대로 두고, `paymentRequired: true`를 더하며, `message`를 안내로 바꾼다. `rawStderrTail`·`sessionId`는
    그대로다.
- **`grok_cli`.** 종료 코드가 0이 아닌 실행의 stderr에서 같은 것을 찾으면 `paymentRequired`와 같은 `message`를 싣는다.
- **배포 프롬프트.**
  - routing 스킬: "매 실행 뒤"에, `paymentRequired`면 다시 시도·resume·새 위임을 하지 않는다는 줄을 더했다.
  - routing 스킬: 2차 순서 3번의 한 줄 — 긴 기계적 작업은 `grok-worker`를 백그라운드로 돌릴 수 있다. 그 실행도 실제 위임이니,
    돌아오면 diff를 검토하고 도는 동안 같은 폴더에 두 번째 위임을 시작하지 않는다.
  - `agents/grok-worker.md`: 규칙 10.
- **문서.** `docs/04`(실패 결과, `grok_cli` 결과, 오류 문구), `docs/07` 8번, `examples/orchestrator-consumer.md`, README 두 판의 문제
  해결, 계약 §17과 머리 표, `docs/09` §4 J, 계획.

## 하지 않는 것

- **새 `status` 값을 만들지 않았다.** 소비자가 `status`로 갈라 둔 흐름이 그대로 돌도록 `grok_error`를 두고 `paymentRequired`를 더했다.
- **다시 보내지 않는다.** 래퍼는 402 뒤에 아무것도 다시 보내지 않고, API 키로 바꿔 보내지도 않는다.
- **사용량이 돌아왔는지 알리지 않는다.** 그 상태를 읽을 길이 없다(`grok_build_status`에는 넣지 않았다).
- **실세션의 다른 402 문구는 재지 않았다.** xAI가 다른 말을 보내면 안내는 "사용량 소진"이 아니라 "402로 거절"로 물러난다.
- **훅은 그대로다.** 402는 실행이 모델에 닿은 뒤에야 알 수 있다.

## 검증

- **새 테스트.** 위치는 `delegate.test.ts`의 402 묶음과 `paymentRequiredReason`, `grok-cli.test.ts`의 402 묶음이다. 실측 원문은
  `test/payment-402-fixtures.ts` 한 곳에 둔다.
  - 기능 테스트 열셋은 고치기 전 소스에서 실패했다(`paymentRequired` 없음, 함수 없음).
  - 대조 다섯은 고치기 전에도 통과한다: 404, 성공한 요약, 인증 먼저, `grok_cli`의 404, exit 0. 바꾸지 않을 동작을 지킨다.
  - 변이 열둘이 모두 테스트를 깨뜨린다:
    - `grok_cli`가 exit 0도 읽기, `grok_cli`가 못 찾기;
    - 위임이 성공한 요약도 읽기, 인증보다 먼저 묻기;
    - 봉투 없는 갈래·빈 plan·성공하지 못한 갈래에서 각각 못 찾기;
    - 아무 "402"나 잡기, 맨 `"http_status": 402`를 무시하기;
    - 구독의 모든 402를 "사용량 소진"으로 말하기, api 모드에 구독 안내 주기, grok 원문을 그대로 두기.
  - 수치는 `npm test`가 원천이다.
