# Grok plugin v0.2.6 — release notes

**Plugin version:** `0.2.6`  
**Previous release:** `v0.2.5`  
**Severity:** Security hygiene — a vulnerable dependency was inlined in the shipped bundle. No
change to MCP server behaviour, auth, or billing.

---

## Summary

The bundle end users execute (`mcp-server/dist/index.js`) contained `fast-uri` 3.1.4, which is
vulnerable to host confusion via a backslash authority introducer
([GHSA-7p8r-x3mc-p8w7](https://github.com/advisories/GHSA-7p8r-x3mc-p8w7), high). This release
ships the patched 3.1.5 parser. Nothing else about how Grok runs, authenticates, or bills has
changed — no tool, command, skill, or hook was touched.

**Is this urgent for you? Realistically, no.** `fast-uri` is reached only through `ajv`'s
schema `$ref`/`$id` resolution, and the only schemas this server validates are its own static
tool schemas. There is no path where an attacker-controlled URI drives a trust decision. It is
shipped as a patch because a vulnerable parser should not sit in a distributed artifact, not
because a live exploit exists here.

---

## What changed

**`fast-uri` 3.1.4 → 3.1.5, and the bundle was rebuilt.** `build.mjs` runs esbuild with
`bundle: true`, so runtime dependencies are inlined into `dist/index.js`. A lockfile bump alone
would have left the shipped artifact vulnerable; the rebuilt bundle carries the real fix
(`parseWithStatus` + authority-introducer validation).

**Other dependency bumps that ship no behaviour change.** `hono` 4.12.29 → 4.13.1,
`ip-address` 10.2.0 → 10.4.0, `nanoid` and `postcss` in the dev tree. None of these appear in
either committed bundle — they belong to MCP SDK HTTP/express transports and the vitest tree,
neither of which this stdio server loads. They are recorded here only so the version bump
accounts for every lockfile change. `npm audit` now reports **0 vulnerabilities**.

**Why this got a version number at all.** The plugin cache is keyed by version
(`~/.claude/plugins/cache/<marketplace>/<plugin>/<version>/`). Republishing a different bundle
under `0.2.5` would leave two distinct artifacts sharing one version string, and
`/grok:status` → `serverVersion` could no longer tell you which one you are running.

## Install / update

```
/plugin marketplace add xzawed/claude-grok-build-plugin
/plugin install grok@grok-marketplace
/reload-plugins
```

Then verify:

1. In a terminal: `claude plugin list` → `grok@…` **Status: enabled**
2. In Claude Code: `/grok:status` → `serverVersion` **0.2.6**
