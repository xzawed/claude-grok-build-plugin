# Grok Build 1.0.3 / Grok 4.6 호환 수리

- 측정일: 2026-08-14
- CLI: **1.0.3 (1a29d5bc12) [stable]**, 기본 모델 **grok-4.6**
- 대상 릴리스: **v0.2.7**
- 라이브 프로브: 격리 scratch git + `runDelegate`/`runGrokCli`/`checkAuth` 실경로

이 문서는 결정 근거다. 헤드리스 계약 숫자는
[`grok-cli-contract.md`](./grok-cli-contract.md)가 SSOT.

## Done (구현 전에 고정)

1. 기본 위임이 라이브 1.0.3에서 `status: "completed"` + `billing: "subscription"` + 실제
   `filesChanged`를 반환한다 (`stopReason: "end_turn"` 포함).
2. `/grok:verify`가 `--check` 없이 스폰되고, 편집 + 검증 문구를 남기며 `completed`가 된다.
3. `best_of_n`은 스폰하지 않고 명확히 거절한다 (1.0에 `--best-of-n` 없음).
4. `--model grok-build`는 스폰 실패가 아니라 **플래그 생략**(CLI 기본 모델)으로 정규화한다.
5. `grok import`는 TUI로 행하지 않는다 — `blocked` + 안내.
6. Windows에서 `HOME`/`GROK_HOME`이 비어 있으면 `buildGrokEnv`가 `homedir()`을 넣어
   `grok du`가 동작한다.
7. 유닛 + typecheck + 번들 재빌드 + 라이브 전표면 재실측이 위 항목을 재확인한다.
8. 버전은 **0.2.7** (번들이 바뀌면 캐시 키를 바꿔야 한다).

제품 본질(`docs/00`)과 충돌하지 않음: 구독 정제·무자동커밋·Claude 리뷰 게이트는 그대로다.
범위 밖: usage 토큰/USD 노출, `--max-turns` 신규 필드, ACP, 이미지/비디오, 라우팅 정책 재설계.

## 실측으로 확정된 파손

| 증상 | 원인 (1.0.3) |
|---|---|
| 파일은 쓰였는데 `grok_error` | JSON `stopReason`이 `"end_turn"` (구 계약 `"EndTurn"`) |
| verify / `/grok:tests` 즉시 실패 | `--check` 삭제 (`unexpected argument`, exit 2) |
| `best_of_n: 2` 즉시 실패 | `--best-of-n` 삭제 |
| `--model grok-build` 즉시 실패 | 모델 id 목록은 `grok-4.6` / `grok-4.5`만 |
| `/grok:import` 행 위험 | `import`는 서브커맨드가 아님 — 위치 인자가 **TUI 프롬프트** |
| `grok du` Windows 실패 | `HOME`/`GROK_HOME` 미설정 (`USERPROFILE`만으로는 부족) |

plan / auth / hook / worktree 수명 / 과금 정제 / TUI denylist는 라이브에서 통과했다.
plan은 `stopReason`을 보지 않아 `end_turn`에도 `completed`였다.

## 결정

### A. 성공 판정

`isSuccessfulStopReason(raw)` — `EndTurn`과 `end_turn`(대소문자 무시)만 성공.
`cancelled`/`Cancelled`는 계속 실패. 원문 `stopReason`은 에러 메시지에 그대로 남긴다.
파서는 필드를 정규화하지 않는다 (관측값 보존). 분류기만 양쪽을 받는다.

### B. verify

`--check`를 붙이지 않는다. `input.check === true`이면 프롬프트 뒤에 고정 영문
자기검증 지시(`VERIFY_PROMPT_SUFFIX`)를 붙인다. 이력 `check: true` 마커는 유지.
`--json-schema`는 최종 `text`를 스키마로 묶어 편집 품질을 해칠 수 있어 **이번 범위에서 제외**.

### C. `best_of_n`

스키마 필드는 남겨 구 클라이언트가 스키마 오류 대신 한국어 거절을 보게 한다.
값이 있으면 spawn 없이 `grok_error`. 스킬/문서에서 추천을 뺀다. 대체 구현(subagent
래핑)은 하지 않는다 — 1.0의 병렬은 에이전트 내부 도구이고 플러그인 표면이 아니다.

### D. 모델 alias

실측된 폐기 id만: `grok-build` → `--model` 생략 (현재 기본 `grok-4.6`).
`grok-4` 같은 미실측 id는 매핑하지 않는다.

### E. import

`isBlockedGrokCommand`가 `import`를 차단. 메시지는 “서브커맨드 없음, TUI 행 방지,
sessions/resume을 쓰라”.

### F. HOME

`buildGrokEnv`에서 `HOME`과 `GROK_HOME`이 모두 비면 `HOME=homedir()`.
이미 있으면 건드리지 않는다. Windows `homedir()` = `USERPROFILE`이라 auth 경로와 같다.

- ACP, usage에 CLI USD 붙이기, `--max-turns` MCP 필드
