# v0.2.12 — GROK_HOME, 열려 있던 차단, 그리고 멈추던 프롬프트

2026-09-02. 계약 문서가 **1.0.3** 기준인데 머신의 CLI가 **1.0.5**라는 것을 발견해 전체 범위를
재실측했고, 그 과정에서 버전 격차와 **무관하게 이전부터 존재하던** 결함 세 건이 드러났다.
(재실측 도중 CLI가 스스로 **1.0.13**으로 자동 업데이트됐다 — 아래 "버전" 절.)

MCP tool 9개는 그대로. 계약 SSOT: `docs/specs/grok-cli-contract.md` (이번부터 **절별 유효 버전**).

## 고친 것

### 1. `GROK_HOME` 사용자가 복구 불가능하게 잠기던 문제 (breaking)

grok README는 `GROK_HOME — Override config directory (default: ~/.grok)`을 문서화하고 있고,
실측 결과 **폴백이 없다**. `GROK_HOME` 아래 토큰이 없으면 `~/.grok/auth.json`이 멀쩡해도
미인증이다.

플러그인은 `~/.grok/auth.json`을 하드코딩하고 있었다. 그래서 `GROK_HOME` 사용자는 PreToolUse
hook에 막히고, **안내대로 `grok login`을 해도 토큰이 `$GROK_HOME/auth.json`에 쓰여** 플러그인이
보지 않는 경로로 갔다 — 빠져나올 방법이 없었다.

배포되는 번들로 대조한 실측 (동일 입력, `GROK_HOME`에 유효 토큰 · 기본 홈에는 없음):

```
v0.2.11 dist/hook.js → permissionDecision "deny"
v0.2.12 dist/hook.js → allow
빈 GROK_HOME         → 여전히 deny (정상)
```

`env.ts`는 이미 `GROK_HOME`을 서브프로세스로 통과시키고 있었다. auth probe만 몰랐다.
바이너리 위치(`GROK_BIN_DIR`||`~/.grok/bin`)는 `GROK_HOME`을 따라가지 **않는다** —
install.sh가 `GROK_HOME`을 읽지 않는 것을 확인했다.

### 2. `/grok:cli` 차단 목록이 fail-open이었다

`grokSubcommand`가 **첫 positional에서 멈춰서**, `VALUE_FLAGS`에 없는 플래그의 값이 서브커맨드로
오인되고 그 뒤의 진짜 서브커맨드는 검사되지 않았다 — `--sandbox workspace dashboard`가 spawn까지
갔다. 실측상 `grok --no-auto-update --sandbox workspace version`은 정말로 flag-value + COMMAND로
파싱된다(exit 0). 코드 주석은 "차단 쪽으로 기운다"고 주장했지만 반대로 동작했다.

1.0.13에 있는데 스냅샷에 없던 값-플래그 8개를 채웠지만, **중요한 건 구조 변경**이다: 이제
denylist 단어를 **positional 어디에서든** 거부한다. 스냅샷이 다시 낡아도(반드시 낡는다 —
이 저장소는 배포하지 않는 CLI를 추적한다) 차단은 계속 옳다. 대가는 예약어 7개와 글자가 같은
인자를 과차단하는 것인데, 이는 명확한 거부로 끝나지 행으로 끝나지 않는다. 거부 메시지는 이제
첫 positional이 아니라 **실제로 걸린 단어**를 지목한다.

### 3. 확인 프롬프트가 호출을 멈추던 문제

`/grok:memory clear`는 60초 타임아웃을 다 쓰고 아무것도 지우지 않았다. grok이
`Are you sure? [y/N]`을 띄우는데 `defaultSpawn`이 아무도 쓰지 않을 stdin 파이프를 물려줬기 때문.

동일 argv, stdio만 다르게 실측 (1.0.13, 실제 메모리 파일이 있는 임시 워크스페이스):

```
stdin=pipe   → 25098ms, 상한에서 강제 종료, exit null, 아무것도 안 지워짐
stdin=ignore →   428ms, exit 0, "Are you sure? [y/N] Cancelled."
```

이 래퍼는 헤드리스 전용(프롬프트는 `-p`/`--prompt-file` argv로 간다)이므로 stdin은 `/dev/null`이
정직하다. 이 수정은 한 커맨드에 그치지 않는다 — `plugin install`(`--trust`),
`plugin uninstall`(`--confirm`), `doctor fix`(`--yes`)도 같은 형태로 묻고 셋 다 denylist에 없다.
열거는 낡지만 구조는 낡지 않는다. `commands/memory.md`는 실제로 지우는 것이 `-y`임을 명시하고,
플래그를 보내기 전에 사용자와 파괴적 의도를 확인하도록 바꿨다.

### 4. 유지보수 프로브가 격리하지 못하고 실제로 과금하던 문제

`npm run probe:unauth`는 "실 홈 손상 없음"이라 적혀 있었지만 `process.env`를 펼쳐서,
개발자에게 `GROK_HOME`이 있으면 격리가 뚫렸다. 실측:

```
HOME/USERPROFILE만 격리                    → "You are not authenticated."  (격리 성립)
+ 호스트 GROK_HOME=~/.grok                 → "You are logged in with grok.com."  ← 실제 세션·과금
```

`GROK_HOME`을 격리 디렉토리로 고정했고, 하드코딩돼 있던 `timedOut: false`도 실제 값으로 바꿨다
(15초에 SIGKILL 당한 실행이 `code: null`인 정상 종료처럼 보고되고 있었다).

### 5. 동승 — `~/.grok-build` 퍼미션 (docs/09 §C 보류 항목)

`worktree.ts`의 `mkdirSync(baseDir, {recursive:true})`가 mode 없이 부모 `~/.grok-build`를
POSIX 0755로 만들 수 있었다(`history.ts`는 0700을 넘긴다). 어느 쪽이 먼저 도느냐에 결과가
달라지면 안 되므로 `WORKTREE_DIR_MODE = 0o700`으로 맞췄다. `docs/09` §C가 정한 재검토 트리거
— *"다음에 진짜 이유가 있는 변경이 생길 때 함께 태운다"* — 를 이번 릴리스가 충족한다.

## 버전 — 세 갈래로 어긋나 있었다

| | 버전 |
|---|---|
| 계약 문서 (v0.2.11 시점) | 1.0.3 |
| 세션 시작 시 설치본 | 1.0.5 |
| upstream stable | 1.0.13 |

**그리고 세션 도중 CLI가 1.0.5 → 1.0.13으로 스스로 업데이트됐다** (바이너리 mtime으로 확인).
이것이 이번 릴리스의 설계 판단을 지배한다: 계약 스냅샷은 관리자가 통제할 수 없는 속도로 낡는다.
그래서 차단 판정을 값-플래그 목록에서 떼어냈고, 계약 문서를 헤더 버전 하나가 아니라
**절별 유효 버전 표**로 바꿨다.

1.0.13에서 재실측한 핵심 계약은 **변화 없음**: exit 0 · `--output-format json` 단일 객체 ·
`stopReason: "end_turn"` · `--always-approve` 헤드리스 편집 성립 · 자동 커밋 없음 ·
`git status --porcelain -z` 정상. 제거된 플래그(`--check`, `--best-of-n`)는 여전히 exit 2,
모델은 `grok-4.6`/`grok-4.5` 그대로.
