# Grok plugin v0.2.10 — release notes

**Plugin version:** `0.2.10`  
**Previous release:** `v0.2.9`  
**Severity:** Resource leaks + one correctness fix in user-facing diagnostics. Auth, the
subscription env strip, `--always-approve` and no-auto-commit are unchanged.

---

## Summary

A leak audit — six parallel dimensions, adversarially verified, then cross-checked with Grok
Build against the running grok 1.0.5 — found that the plugin never cleaned up after itself.
Every isolation worktree left a permanent git branch behind, and nothing ever removed the
worktree directories: **37 of them, ~398 MiB**, had accumulated on the author's machine, with
evidence of an earlier manual archive of 18 more.

The audit also confirmed the important negative result: **the billing-safety invariant holds.**
A sentinel planted in every credential-carrying variable at once showed all five spellings of
`XAI_API_KEY` / `GROK_CODE_XAI_API_KEY` stripped in subscription mode, no credential in
`~/.grok-build/history.jsonl`, and no credential reaching a child process or the model through
any exit that the plugin controls.

---

## What changed

- **Isolation worktrees no longer leak a branch.** `createGrokWorktree` makes a `grok/<name>`
  branch and nothing ever deleted it, so every `worktree: true` delegation permanently added one
  to the user's repo. `remove` now also runs `git branch -d` — `-d`, not `-D`, so git refuses when
  the branch holds unmerged commits and the tool reports `branchDeleted: false` instead of
  destroying work grok actually committed there.
- **New `prune` action** on `grok_build_worktree`: finds trees under `~/.grok-build/worktrees`
  older than `max_age_days` (default 7). **Dry run unless `apply: true`** — a stale worktree can
  still hold changes that were never applied, so the default only reports candidates. One failure
  does not abort the rest.
- **Every git call is bounded.** `defaultRunGit` had no `timeout` and no `maxBuffer` while its
  sibling `defaultCaptureGit` had both. Git can block indefinitely (a stdin-reading plumbing
  command, a credential helper, a contended lock), and `createGrokWorktree` / `applyGrokWorktree`
  run *before and outside* the grok spawn timer — so a hung git made `runDelegate` ignore its own
  `timeout_ms` and never settle. Both runners now share one bounded entry point.
- **Subprocess output is capped.** `defaultSpawn` accumulated stdout and stderr with no limit, so
  a runaway run (a large `grok export`, a `--debug` flood through `grok_cli`) grew the server heap
  until V8 threw inside the `data` handler and took the MCP server with it. stdout keeps its head
  (16 MB — a small valid result JSON always survives intact); stderr keeps its tail (1 MB — only
  the last few hundred characters are ever surfaced).
- **`~/.grok-build/` and `history.jsonl` are created owner-only** (`0700` / `0600`). They hold
  200-character prompt previews and absolute cwd paths — the user's project text — and the Node
  defaults left them world-readable on a shared POSIX host, while the apply patch file was already
  written `0600`. Note: `mode` applies at creation, so a history file that already exists keeps
  its current permissions.
- **The billing-mismatch diagnostics no longer blame a leaked API key.** `status.ts`, `usage.ts`
  and `orchestrator.ts` told the user that a `metered_api` tag or `billingMismatch` meant a stray
  key had overridden the session. It cannot: the tag is `billingFor(mode)`, so only
  `GROK_BUILD_AUTH_MODE=api` produces it, and subscription mode strips the key variables before
  spawn. These strings reach Claude through `grok_build_status`, so the wrong diagnosis was being
  acted on. v0.2.9 corrected the same claim across the documentation; this finishes it in code.

## Tests

The suite grew by nineteen cases (`npm test` is the SSOT for the count). New coverage includes a
real bounded-git test that runs a git command which would otherwise block forever and asserts it
is killed, plus the full prune matrix (dry run, age threshold, apply, partial failure, relative
cwd, missing base dir).

---

## Upgrading an existing install

Worktrees and branches that accumulated before this release are not touched automatically. To
see what is there and reclaim the space:

```
/grok:worktree prune              # dry run — lists candidates only
/grok:worktree prune apply        # removes them, and their grok/<name> branches
```

Review anything you are unsure about with `action: "diff"` first.

---

## How to update

Marketplace update/reinstall → `/reload-plugins` → `claude plugin list` enabled →
`/grok:status` `serverVersion` **0.2.10**. Cache is version-keyed; do not reuse 0.2.9.
