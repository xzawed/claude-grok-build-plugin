# v0.2.36 — 전체 감사가 찾은 결함 12건 (A37~A48)

2026-09-25. 오너가 요청한 전체 감사(코드·문서, 로컬 SonarQube 서버 + Grok)에서 **두 가지 이상의 독립 방법으로
다시 잰** 결함 12건을 고쳤다. 오너가 "확인된 결함 모두를 Grok과 함께"로 착수를 맡겼다. SonarQube가 준 신뢰성 D·보안 C는
오탐과 설계상 선택이 만든 등급이었고(서버·eslint-plugin-sonarjs·Grok 분류·소스 판독이 일치), 아래 결함은 그 등급 밖에 있었다.

## 무엇이 바뀌나

- **A37 (`history.ts`):** 두 규칙이 차례로 돈다. **먼저 v0.2.35가 내보낸 대입 규칙을 한 글자도 바꾸지 않고**
  (`SHIPPED_ASSIGNMENT`) — 이것이 바닥이다. 새 규칙은 그 위에서 **더 가리기만** 하므로, 옛 가림이 가리던 것은 무엇도
  다시 새지 않는다(아래 "머지 전 검토": 새 규칙을 다듬을 때마다 옛 가림이 가리던 것을 흘렸다). 새 규칙은 `name =`/`name:`
  모두를 후보로 두고 **이름이 결정한다**: `_ . -`와 camelCase로 나눈 마지막 성분(`PassWord`는 한 낱말)이 자격증명 단어인지 —
  password·secret·token·passphrase·`accesskey` 같은 붙여 쓴 키, 앞에 무엇이 붙은 긴 단어(`PGPASSWORD`), 뒤의 숫자
  성분(`DB_PASSWORD_2`), 한정된 `key`(api·access·secret·private·encryption·signing·account·master·hmac). 이름 붙은 키와
  환경 변수 모양(UPPER_SNAKE) 이름은 그 자체로 증거라 값이 그럴듯하기만 하면 가리고, 코드·산문 모양의 이름과 점 붙은
  이름에 인용 없이 붙은 값(`self.DB_PASSWORD = password`)은 불투명해야 가린다. 새 규칙이 남기는 것: **안에 든 것이 이름인**
  자리표시(UPPER_SNAKE이거나 숫자 없는 글자 — `$uperS3cretPassw0rd`·`$SUMMER2024X`·`<hU7x…>`는 가린다), 기본값이 없는 셸
  참조(`${X:-v}`는 `v`로 판단), 세는 단어 뒤의 **짧은** 숫자(`token` 뒤 7자리·`pass` 뒤 3자리까지 — `MAX_OUTPUT_TOKEN=128000`),
  플래그·타입(`yes`·`enabled`·`SecretStr`), 인용 없는 **소문자로 시작하는 호출**(`z.string().min(32)`·`getPassword()` —
  `Summer(2024)`·`ENC(…)`는 가린다), 빈 값 다음 줄의 UPPER_SNAKE 대입. 인용 없는 값을 둘러싼 닫는 문자(`)`·`]`·백틱·
  마침표·`;`)는 가림 밖에 남긴다(불투명 판정은 자르기 전 길이로). 후보는 **구분자에서 끝나고** 값은 자격증명 이름일 때만,
  **가리든 않든 한 번** 읽고 지나간다 — 그래서 `$env:DB_PASSWORD=`는 `env:` 뒤에서 찾히고 `k=k=k…`·`pwd=${…`도 선형이다.
  256자를 넘는 이름은 자격증명 이름이 아니다(7M자 이름이 정규식 스택을 넘겼다).
- **A38 (`worktree.ts`):** 소유자는 마지막 `/worktrees/<name>` 앞(끝의 `/.git`은 뗀다) — bare(`proj.git`·`.bare`),
  서브모듈(`.git/modules/<sub>`), git 2.48의 상대 gitdir까지. 상대 gitdir는 git처럼 트리의 **실제 경로**에서 푼다(기준
  폴더가 심볼릭 링크·정션 너머여도). **읽지 못한 소유자는 "사라짐"이 아니라 "모름"**이고 모름은 보호된다. 소유자가
  정말 없으면(A5의 고아) 여전히 거둔다.
- **A39·A41·A46 (`delegate.ts`):** `defaultSpawn`은 `spawnBounded('grok', …)`가 됐다 — 동기 예외와 파이프 없는
  자식(파일 서술자가 바닥났을 때, EMFILE)을 `spawnError`로, 파이프의 `'error'`도 듣는다(win32에서 260자 이상의 작업
  폴더는 ENOENT 뒤 파이프가 ENOTCONN을 내고, 아무도 듣지 않아 서버가 죽었다). grok의 `exit`에서 캡을 멈추고 `EXIT_GRACE_MS` 유예 뒤
  (POSIX는 그룹을 거두고) 파이프를 놓는다. 유예는 캡에서도 시작해 **kill이 실패해도** 호출이 끝난다. 실패한 kill은
  더는 "시작 실패"로 읽히지 않는다. `--prompt-file`은 `promptFitsArgv`의 플랫폼별 한도를 넘는 프롬프트에만 쓴다 —
  Linux에서는 argv의 실제 한도(인자 하나의 바이트)이고, win32에서는 인용이 인자를 두 배로 늘리는 최악에 맞춘 값이라
  평범한 글 15,000~약 32,000자도 파일로 가며, macOS는 재지 않아 Linux 값을 쓴다. 파일은 비공개 `mkdtemp` 폴더에
  쓰고(POSIX에서 0600) `finally`에서 지운다. 네 도구의 `timeout_ms`는 2147483647이 상한이다.
- **A40 (`usage.ts`):** 문자열이 아닌 `cwd`는 디렉터리 일치가 아니고, 문자열이 아닌 `ts`는 첫/마지막 시각에 들지 않는다
  (`{"toString":0}`처럼 변환할 수 없는 값도).
- **A42 (`delegate.ts`):** plan의 두 반환 경로가 `finish`를 탄다(B1·B3). HEAD가 움직이면 `committed: true`이자 쓰기이고,
  메시지는 `git status`가 아니라 `git show HEAD`를 가리킨다(`/grok:plan`이 그 메시지를 보여준다). 지문에 untracked 파일을
  넣었다 — **모든** 파일의 크기·수정 시각(`lstat`, 32개씩 병렬)과, 목록 앞쪽 `UNTRACKED_HASH_MAX_FILES`개의 **내용**(32 MiB까지,
  stat이 말한 길이만큼만 읽는다). 심볼릭 링크는 따라가지 않고 가리키는 경로로 센다(`/proc`를 가리키는 링크를 따라가면
  읽기가 끝나지 않았다). 남는 사각: 앞쪽 N개 밖에서 크기가 같고 수정 시각까지 되돌린 재작성. porcelain 경로는 저장소 루트
  기준이므로 `--show-toplevel`에서 읽는다(줄 끝만 떼고 — 폴더 이름 끝의 공백은 이름이다).
- **A43:** 라우팅 넷·`normalizeCwd`·`semverOf`는 Grok이, 가림 셋(URL은 `://`에 고정, JWT는 base64url 덩어리 단위
  스캐너, PEM 블록은 다음 BEGIN에서 멈춤)은 A37과 함께. `s3 rm … --recursive`는 정규식 대신 한 번 훑어 본다(`rm`이 있는
  줄에서 그 뒤 `--recursive`; `s3`와 `rm` 사이의 줄바꿈도 전처럼 허용).
- **A44 (`routing.ts`):** "2개 이상의 파일"은 `file` 앞의 수를 **거꾸로** 읽는다 — `1,000`·`1.000`·`1 000` 같은 천 단위와,
  다른 수 뒤의 수(`in 2024 10 files`, `v1.2 100 files`)도. `.`·`,` 바로 뒤의 수(`2.5 files`)와 앞자리 0은 개수가 아니다.
  `token`/`tokens`(`refreshToken` 안도)는 세거나 쪼개는 뜻이 아니면 보안 신호다 — 앞의 **낱말**이 `max`·`input`·`design`·
  `next`… 이거나 뒤가 `count`·`limit`·`usage`…인 경우, 또는 `tokenizer`. 낱말 경계가 있어 `admin`은 `min`이 아니다.
- **A45 (`git-porcelain.ts`, 새 리프 모듈):** `delegate.ts`·`worktree.ts`의 바이트 동일 사본을 하나로 — 결함을 두 번
  고쳐야 했던 이유를 없앴다. untracked 경로 판독도 여기(A42가 쓴다).
- **A47·A48:** hook의 설치 확인 한 번, probe의 `throwawayHomeEnv`(새로 `synthetic-auth.mjs`에) + `detached`.

## 전후 실측

- **감사 페이로드를 같은 입력으로 다시 쟀다.**
  - 재빌드한 배포 번들 e2e(쿼터 0 — 임시 홈, 합성 세션, `node.exe` 사본을 `grok.exe`로):
    - A40 — `cwd`를 준 `usage`·`status`: `isError`("reading 'split'") → 정상(total 1).
    - A39 — 40,000자 위임: `"spawn ENAMETOOLONG"`(이력 0줄) → 실제로 시작(가짜 grok이 인자를 받았다), 구조화된 오류 + 이력 1줄.
  - 함수 수준: A37 9/9 가림, A44 영어 토큰 작업 HIGH·"in 1 file" MEDIUM, A38 bare 레이아웃 삭제 1 → 0, A39 40,000자 인자
    `reject` → `spawnError`, A46 3e9 캡이 3초 자식을 끝까지 둠, A41 손자 사례 8.1초 → 2.07초·`timedOut: false`.
- **실제 grok 1회(구독, 1.0.41):** 9,134자 프롬프트, 유일한 지시는 맨 끝 → `--prompt-file`로 넘어가 grok-4.7-build가
  `PROMPTFILE_OK`로 정확히 답했다. 남은 `grok-prompt-*` 폴더 0. (그때 한도는 8,000자였다 — 지금 그 길이는 argv로 간다.
  잰 것은 grok이 파일을 프롬프트로 읽는다는 사실이다.)
- **정규식:** 재작성을 원본과 무작위 입력 20만 개(고유 115K~127K)로 차등 비교 — 불일치 0. 최악 입력(64K자) 최대 5.3초 →
  1ms 이하. 가림은 64K자 `eyJ-eyJ-…` 1.87초 → 1ms.
- **POSIX 그룹 kill(A48):** Linux 컨테이너(node:22-bookworm)에서 detached 없이 띄운 자식은 `ESRCH`로 살아남고, detached면
  SIGKILL로 죽는다.
- **bare 레이아웃(A38):** 실제 git 2.45에서 `gitdir: …/proj.bare/worktrees/<n>` — 옛 정규식 일치 0.

## 하지 않는 것

- **가림은 여전히 완화다.** 옛 가림에서도 새던 형태 중 몇은 이번에 막았지만(`PGPASSWORD`·`HMAC_KEY`·
  `POSTGRES_PASSWORD=12345` 등), 다음은 여전히 샌다 — 한 단어 이름의 짧은 값(`PASSWORD=hunter2`, `PGPASSWORD=postgres`),
  코드 모양 이름의 12자 미만 값(`DBPassword: hU7xK2pQ9zL`), 공백·쉼표·따옴표·`}`가 든 값, 닫히지 않은 인용, 이스케이프된
  JSON, `os.environ["X"] =`, `SSHPASS`·`dbpwd`·`APP_KEY`·`SECRET_KEY_BASE`·`SUPABASE_SERVICE_ROLE_KEY`·`SESSION_KEY`·
  `ConnectionStrings__Default`, docker의 `"auth":`, `Token`/`Bot` 인증 스킴, Slack webhook 경로, `rk_live_`/`glpat-`
  형태(적대 검토의 40형태 중 18이 옛 가림과 같이 샌다). 또 하나 — 앞 값에 `;`·`&`·`|`로 붙은 이름 뒤에 **띄어 쓴**
  구분자가 오면(`secret: db;password = …`) 그 이름은 앞 값의 일부로 읽힌다. 옛 가림도 같았고, 새 규칙이 그것을 찾으려
  값 안을 다시 읽던 판은 2차 시간이었다.
- **과잉 가림 몇은 절충으로 남겼다.** 환경 변수 이름 뒤의 산문(`Rotate DB_PASSWORD: it was exposed` → `it`),
  `RENDER_PASS=shadow`·`EOF_TOKEN=eof`·`DB_SECRET=db-credentials`·`HMAC_KEY=sha256`, 숫자 섞인 경로·태그
  (`token=src/…/Button.v2.tsx`, `signingKey=release-2024`), 인용 없는 값 안의 `;` 뒤(`DB_PASSWORD=hunter2;DB_HOST=db`는
  뒤까지 가린다 — 연결 문자열의 `;`를 지키려고), 대문자로 시작하는 호출 모양 타입(`API_TOKEN: Optional[str]` —
  `Summer(2024)`와 모양이 같다). 바닥 규칙의 버릇도 그대로다 — 이름 붙은 키의 값은 코드여도 가리고
  (`DATABASE_URL: z.string().url()`), 옛 이름 뒤 값은 닫는 문자까지 가린다(`password: … .`의 마침표). 반대쪽 절충:
  소문자로 시작하는 호출 모양 비밀(`summer(2024)`)은 코드로 읽혀 남는다. `PIN_TOKEN=4839201`처럼 `token` 뒤 7자리
  이하 숫자도 설정으로 남는다.
- **win32의 손자 프로세스는 여전히 살아남을 수 있고, POSIX에서도 자기 그룹을 만든 손자는 그렇다** — 끝나는 것은
  호출이다(`docs/06` "플랫폼 지원").
- **재지 않은 것:** Linux·macOS에서 grok이 `--prompt-file`을 읽는지, 모든 플랫폼에서 `--sandbox`와 `--prompt-file`의
  조합(파일이 프로필 밖이면 막힐 수 있다), macOS의 argv 한도. win32의 평범한 글 15,000~약 32,000자와 macOS의
  131,000바이트 이상은 전에는 argv로 가던 길이다 — 이제 파일로 간다(계약 §1).
- **감사의 문서 항목은 이 릴리스 범위 밖이다** — `docs/09` §4 E. 이 릴리스가 바꾼 계약에 닿는 문서만 맞췄다.
- **SonarQube의 스타일 지적은 이 릴리스가 새로 만든 것만 고쳤다**(중복 문자 클래스·정규식 복잡도·인지 복잡도 일부) —

- **구현:** A40·A43(라우팅·usage·semver)·A44·A47·A48은 Grok이 격리 worktree에서 구현했다 — 계약은 먼저 커밋한 실패
