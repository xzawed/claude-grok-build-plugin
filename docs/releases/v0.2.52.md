# v0.2.52 — `grok_cli`가 서브커맨드도 프롬프트도 없는 실행과 프롬프트 없는 `--memory-flush`를 띄우지 않는다 (§4 F · A63)

2026-11-04. 위치 인자가 하나도 없고(`--` 뒤에도) 프롬프트 플래그도 없는 `grok_cli` 인자 — `-w <이름>`·`-c`·`-r <id>`·
`--always-approve`·`--` 단독 같은 — 를 받으면 grok은 보낼 것 없는 대화형 UI를 열었다(이을 세션이 없는 `-c`는 바로 오류로 끝났다).
헤드리스에는 답할 사람이 없어 시간 제한(기본 60초)까지 매달렸고, `-w`는 그사이 저장소에 grok worktree를 등록한 채 남겼다. A52(v0.2.42)는
이런 플래그 뒤의 **맨 단어**만 막았고, 단어가 없으면 그대로 spawn했다. `docs/09` §4 F가 이것도 막을지를 오너 판단으로 두었고, 2026-11-04에
오너가 남은 판단을 권장안대로 하라고 맡겨 막기로 했다. 같은 릴리스가 `docs/10` A63도 닫는다 — 숨은 스위치 `--memory-flush`는 grok
1.0.44에서 이전 세션의 프롬프트를 실은 대화형이 아닌 요청을 인증 확인도 위임 이력도 없이 보냈다. 대화형 UI를 여는 실행이 아니므로(1.0.70에서는
요청이 `headless`로 표시됐다) 따로 거부한다 — 프롬프트 플래그가 없으면 서브커맨드가 있어도.

## 재현 (쿼터 0 — grok 1.0.70, win32, 실제 `~/.grok` 미접촉)

버릴 홈(`HOME`·`USERPROFILE`·`GROK_HOME`·`APPDATA`·`LOCALAPPDATA`·`CLAUDE_CONFIG_DIR`)에 합성 세션을 두고, grok의 API 주소 둘을 모든
요청에 404로 답하며 요청을 적는 루프백으로 돌렸다 — 아무것도 거절하지 않으므로 브라우저 로그인이 시작되지 않는다(계약 §7 E). 번들을
stdio로 띄워 같은 인자 목록을 차례로 `grok_cli`(`timeout_ms: 15000`, `cwd`는 버릴 git 저장소)에 보냈다. v0.2.51 열은 이 PC에 설치된 0.2.51
캐시의 번들(`dist/index.js` sha256 `b23c42a6…` — CRLF를 빼면 태그 blob과 같다), v0.2.52 열은 이 릴리스의 최종 번들(sha256 `9163443d…`)이다 —
하네스가 잰 번들의 해시를 결과 파일에 함께 적었다. 측정 뒤 grok 프로세스는 남지 않았다(`Win32_Process`).

- 대화형 UI를 연 모양(`-w`·`--always-approve`·`--`·`-mp`)의 요청은 1건씩을 빼고 모두 `x-grok-client-mode: interactive`였다. 플러시 모양은
  9건 중 8건이 `headless`, 1건은 그 헤더가 없었다 — 대화형 UI가 아니다. `--memory-f`·`--memory`·`--memory_flush`는 grok의 clap이 거부했다
  (exit 2, 버릴 홈에서 grok 직접 실행) — 접두어를 추론하지 않으므로 규칙은 정확한 철자만 본다.
- `["-c"]`는 이 폴더에 이을 세션이 없어 바로 끝났다 — 세션이 있으면 같은 UI로 그 세션을 이을 것이다(재지 않았다: 이 폴더의 `-p` 실행은
  실패했고, 그 뒤에도 `-c`는 세션을 찾지 못했다).
- A63의 두 모양은 1.0.70에서 세 설정(맨 `-p` 시드, `--experimental-memory`를 붙인 시드, `config.toml`의 `[memory]`·`[memory_v2]`
  `enabled = true`) 모두 모델 요청 없이 끝났다. 시드 턴은 모두 404로 실패했으니 턴이 끝까지 간 세션은 재지 않았다. 서브커맨드와 함께면
  1.0.70은 그 서브커맨드만 돌렸다(위 표). 1.0.44의 기록(이전 세션의 프롬프트를 실은 대화형이 아닌 POST)은 계약 §16에 있다. 이 거부는
  grok 버전과 상관없이 그 모양을 spawn하지 않는다.

## 고친 것 (`mcp-server/src/grok-cli.ts` — 응답 필드는 더하지 않았다)

- `memoryFlushRun`(A63): `--` 앞에 `--memory-flush`가 있고 프롬프트 플래그가 없으며 도움말·버전도 아니면 참이다 — 서브커맨드가 있어도.
  `runGrokCli`는 거부 목록과 맨 단어 규칙 뒤에 이것을 보고 spawn 없이 `blocked`를 돌려준다. 메시지는 그 스위치가 무엇을 했는지와
  `/grok:memory`·터미널을 말한다. 프롬프트 플래그가 있는 실행은 hook이 막고 이력이 적는 프롬프트 실행이라 그대로 돈다.
- `promptlessRun`(§4 F): A52가 쓰는 `parseGrokArgs`로 인자를 읽어, 위치 인자가 없고(`--` 뒤 포함) 프롬프트 플래그가 없으며 도움말·버전
  (`PRINTS_AND_EXITS`)도 아니면 참이다. `memoryFlushRun` 다음에 본다. 메시지는 `grok_build_delegate`(이어 하려면 그 `resume`·
  `continue`), `worktree create`, `--help`·`--version`, 그리고 터미널을 가리킨다.
- 값 플래그의 값과 `-w`·`-r`의 선택 값은 위치 인자가 아니다(`-mp`는 `--model p`, `-wp`는 이름이 `p`인 worktree — 프롬프트가 아니다).
  표에 없는 플래그만 있는 실행도 거부된다 — 새 스위치라면 같은 UI이고, 새 값 플래그의 값은 서브커맨드가 아니다. 찍고 끝나는 새 플래그는
  `PRINTS_AND_EXITS`에 넣을 때까지 거부된다(닫힌 쪽 — 메시지가 터미널을 가리킨다).
- 맨 단어 규칙(위치 인자가 있어야 한다)과 `promptlessRun`(없어야 한다)은 겹치지 않는다. 거부 목록과는 겹칠 수 있다 — 거부 목록의 위치
  스캔은 `-w`·`-r`이나 숨은 플래그의 값을 위치 인자로 읽어(`["-w","dashboard"]`), 먼저 도는 그쪽의 메시지를 받는다.
- hook은 그대로다. 이 실행들은 대개 턴을 쓰지 않는 것으로 판정돼(`mayRunTurn`) 로그아웃 상태에서도 통과하고, 거부는 도구가 spawn 전에 한다.
- `grok_cli` 도구 설명, `commands/cli.md`, `docs/04` §5, 계약 §16이 새 거부를 말한다.

## 함께 정한 것 — `grok_cli`의 `--debug-file` (`docs/09` §4 F)

1.0.70에서 다시 쟀다(같은 하네스, 가짜 자격증명): 만료 전 세션, 모델 자체 키와 그 모델의 `extra_headers` `Authorization`, api 모드의 env
키 — 세 상태 모두 로그(약 58–63 KB)에 평문이 없었고 `SamplerConfig`에 `[REDACTED]`가 있었다. 루프백이 받은 것은 세션 JWT, 그 헤더 값,
env 키다(모델 자체 키는 헤더가 대신해 요청에 실리지 않았다). 1.0.41·1.0.44는 잰 상태 가운데 일부에서 평문으로 남겼다(무엇이 남는지는
상태에 따라 달랐다 — 계약 §10). 만료돼 갱신이 실패하는 세션은 재지 않았다. 프롬프트나 서브커맨드와 함께면 거부하지 않고 문서로 두기로
했다(그것만 있는 실행은 위의 거부에 걸린다). `commands/cli.md`는 사용자가 청하지 않으면 `--debug-file`을 붙이지 말고, 청하면 로그할
서브커맨드나 프롬프트와 함께 넘겨 로그를 저장소 밖에 두고 자격증명이 있을 수 있다고 말하라고 한다. `SECURITY.md`가 1.0.70 측정을 적는다.

## 하지 않는 것

- hook을 바꾸지 않았다. `--memory-flush`는 여전히 "턴을 쓰지 않음"으로 판정된다 — A63의 원래 최소 수정 후보(`mayRunTurn`이 그것을 턴으로
  보고 이력에 적기)는 하지 않았다. 프롬프트 없는 그 실행 자체가 없어졌다.
- 프롬프트가 있는 실행(`-p` 등)과, `--memory-flush` 없이 서브커맨드가 있는 실행은 그대로 돈다.
- 이 거부에는 `accept-release` 칸을 만들지 않는다 — 옛 번들은 이 모양을 spawn해 캡까지 매달리거나 worktree를 남긴다(A52와 같은 까닭,
  `docs/10` A61).

## 검증

- 새 테스트(`grok-cli.test.ts`)는 고치기 전 소스에서 거부할 모양이 모두 실패했고(spawn) 그대로 둘 모양은 통과했다. 고친 뒤 모두 통과한다.
  두 규칙의 변이 아홉 — 도움말·버전 예외 빼기(둘 다), 위치 인자 검사 빼기, 프롬프트 검사 빼기(둘 다), `extractPromptRun` 대신 `mayRunTurn`,
  `--` 경계 무시, 규칙을 부르지 않기(둘 다) — 이 모두 테스트를 깨뜨린다. 수치는 `npm test`가 원천이다.
- 다시 잰 것: 위 표의 v0.2.52 열 — 같은 인자, 같은 하네스, 최종 번들.
- 머지 전 검토(독립 리뷰어 한 명 — 오너가 정했다). 지적은 원자료(결과 파일)로 다시 확인한 뒤에만 고쳤다.
  - 1회차 BLOCKER 0·MAJOR 1·MINOR 4·NIT 4. MAJOR는 `--memory-flush`를 대화형 UI로 묘사한 문장들이었다(1.0.70 실측은 `headless`) — 따로
    둔 거부와 메시지로 고쳤다. 나머지(과장된 문장 다섯 — 평문 기록의 범위, 루프백이 받은 자격증명, 측정한 번들, A63이 닫힌 범위, 예약 작업을
    찾은 범위 — 와 테스트 보강 `-mp`·`-wp`·실제로 겹치는 `["-w","dashboard"]`, 테스트 이름)도 고쳤다.
  - 2회차 BLOCKER 0·MAJOR 1·NIT 3. MAJOR는 첫 커밋의 메시지가 squash 본문(이 레포의 설정 `COMMIT_MESSAGES`)에 그대로 남는다는 것이었다 —
    브랜치를 최종 트리에 대해 참인 메시지 하나의 커밋으로 합쳤다. NIT(모드를 적은 설정은 하나뿐이라는 범위, 1.0.44의 요청은 기록대로 "대화형이
    아닌", 문구 둘)도 고쳤다. 리뷰가 남긴 미측정 하나(줄이거나 바꾼 철자)는 재서 닫았다(위).
  - 1회차가 옮긴 숫자 하나(플러시 요청 "9건 모두 headless")는 원자료가 8건이라 따르지 않았고, 리뷰어도 2회차에서 그렇게 확인했다.
- Grok 반증(5단계)은 하지 않은 채 머지했다 — 2026-11-04 Grok Build 사용량 소진(402)으로, 오너가 머지를 승인하며 Grok 검토를 사용량이
  돌아올 때까지 보류했다. 돌아오면 이 릴리스의 코드를 그대로 주고 반증시키며, 실측으로 확인한 지적만 `docs/10`에 새 번호로 연다.
