# 00. 제품 본질 (Product Vision)

이 문서는 **왜 이 플러그인이 존재하는가**의 원천(SSOT)이다.
구현 상태·Phase 체크리스트는 `docs/06-roadmap.md`, 에이전트 즉시 컨텍스트는 루트 `CLAUDE.md`.

## 한 문장

개발자가 **Grok을 잘 쓰게** 돕고, Claude Code 플러그인을 통해 **Grok이 얼마나 좋은 코딩 AI인지**를
체감하게 하며, Claude와 Grok이 **역할을 나눠 협업하는 멋진 경험**을 만든다.

## 세 가지 목표 (우선순위 순이 아니라 동시에 추구)

| 목표 | 의미 | 제품이 해야 할 일 |
|---|---|---|
| **Grok을 잘 쓰게** | 설치·인증·위임·검토·과금이 마찰 없이 이어진다 | 구독 우선 과금 안전, 명확한 실패 안내, plan→delegate→verify, worktree 격리 |
| **Grok의 실력 체감** | 사용자가 “Grok이 이런 일을 이렇게 빨리/잘 한다”를 느낀다 | 병렬·대량·저리스크 작업에서 Grok 강점을 드러내는 UX(프리셋, best-of-n, 성공 사례 온보딩) |
| **Claude ↔ Grok 협업** | 경쟁이 아니라 오케스트레이터(Claude) + 워커(Grok) | 라우팅 기준(`docs/05-routing-policy.md`), Claude 최종 리뷰, 자동 커밋 금지, provenance |

## 역할 분담 (경험의 뼈대)

```
사람     — 의도·품질 게이트 소유, 커밋 결정
Claude   — 오케스트레이터: 판단, 설계, 위험 작업, Grok 결과 검수
Grok     — 워커: 대량·반복·탐색·보일러플레이트·테스트 백필 등 실행
플러그인 — 안전한 다리: 과금 경로 보호, 헤드리스 계약, 구조화 결과, 이력
```

- Claude를 대체하지 않는다. **Claude 세션 안에서 Grok을 쓰게** 한다.
- Grok을 모든 작업에 밀어 넣지 않는다. 잘못 위임된 실패 사례는 Grok 평가를 깎는다.
- 구독(SuperGrok / X Premium+) 사용이 기본 가치 제안이다 — “이미 내는 플랜으로 워커를 돌린다”.

## 성공의 감각 (정성 지표)

기계 지표(테스트 수 등)는 코드/CI가 원천이다. 제품 감각은 아래로 판한다.

1. **첫 성공까지 짧다** — setup → 샘플 위임 → `billing: "subscription"` 확인.
2. **다시 맡기고 싶다** — diff가 검토 가능하고, 위험 작업은 worktree로 버릴 수 있다.
3. **역할을 이해한다** — 사용자는 “Claude가 시키고 Grok이 치고 Claude가 본다”를 자연스럽게 한다.
4. **Grok이 빛난다** — 대량/병렬 작업에서 Claude 단독보다 체감 이득이 난다.

## 의도적으로 하지 않는 것 (본질과 충돌)

- 자동 커밋 / 자동 PR — 품질 게이트를 플러그인이 훔치지 않는다.
- 호출별 과금 모드 오버라이드 — 구독 신뢰가 깨지면 “Grok을 잘 쓰게”가 성립하지 않는다.
- 모든 작업을 Grok에 강제 — 쇼케이스가 아니라 사고 사례가 된다.

상세 스코프 제외: `docs/06-roadmap.md`. 과금 절대 원칙: `docs/02-auth-strategy.md`.

## 다음 제품 방향 (구현 전 나침반)

Phase 1~3은 **안전한 다리**를 완성했다. 본질을 더 밀려면 다리가 아니라 **경험**을 키운다.

| 방향 | 본질과의 연결 | 상태 |
|---|---|---|
| 라우팅 skill / 프리셋 커맨드 | Claude가 알아서 Grok을 제안 → 사용·체감↑ | ✅ Slice A (`skills/grok-routing`, `/grok:tests|migrate|boilerplate`) |
| 온보딩 첫 성공 강화 | setup → 샘플 위임 → billing 확인 | ✅ Slice A (`/grok:setup`) |
| `best-of-n` · model · resume 등 CLI 강점 노출 | Grok 차별점이 tool 표면에 보여야 체감됨 | 미구현 |
| worktree list/diff/apply/cleanup | 위험 작업도 맡기기 쉬운 협업 루프 | 미구현 |
| usage의 “구독 활용” 피드백 | 잘 쓰게 + 다시 쓰게 | 집계만 있음, 설득 리포트 미구현 |
| Phase 4 오케스트레이터 라우팅 | 시스템 스케일의 Claude↔Grok 협업 | 로드맵 미완 |

우선순위·체크리스트 갱신은 `docs/06-roadmap.md`에서 한다. 이 문서는 **왜**만 고정한다.

- **지금 무엇을 알아야 하는가** → 루트 `CLAUDE.md` (짧게 유지, 이력 금지)
- **왜 / 제품 목표** → 이 문서
