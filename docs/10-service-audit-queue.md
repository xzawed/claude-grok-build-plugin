## 이 항목들을 어떻게 재현하나

**절차의 원천은 루트 `CLAUDE.md`의 "작업 수행 방법"이다** — 여기 있는 건 그 1번 단계를 이 큐에
맞게 적은 것뿐이다. 큐는 언젠가 비지만 절차는 남아야 하므로, 방법을 이 문서로 옮겨 적지 말 것.

배포 번들을 `.mcp.json`이 하는 것과 **똑같이** stdio로 띄워 채점한다 — 세션의 MCP 프로세스는
설치 시점 버전에 고정돼 있어 그걸로 채점하면 엉뚱한 산출물을 채점하게 된다.

```bash
node .claude/tools/mcpcall.mjs list
node .claude/tools/mcpcall.mjs call grok_auth_check '{}'      # serverVersion 으로 대상 확인
GROK_BUILD_AUTH_MODE=api node .claude/tools/mcpcall.mjs call grok_auth_check '{}'
```

53개 항목을 실행하고 각 항목을 **독립 재실행자**가 재측정했다. 원 결과: PASS 29 · DEGRADED 20 ·
FAIL 4. FAIL 4건은 v0.2.19로 나갔다(`docs/releases/v0.2.19.md`).

⚠️ **이 문서는 요약이다.** 항목별 원본 페이로드와 재실행 근거는 감사 세션의 subagent 트랜스크립트에
있었고 그건 레포 밖·세션 로컬이라 사라진다. 어떤 항목을 의심하면 **다시 재는 것이 정답**이다 —
위 하네스로 해당 항목만 재현하면 되고, 그게 이 문서가 "재현 방법"부터 적는 이유다.

⚠️ 실제 위임을 돌리므로 **구독 쿼터를 쓴다**. 시험은 반드시 버릴 디렉터리에서, 프롬프트는
작게, `~/.grok`은 절대 건드리지 않는다(`grok login`/`logout` 금지).

### A21. 9개 중 8개 도구가 광고한 `additionalProperties: false`를 지키지 않는다 (`server.ts`)

**오타 난 필드 이름이 조용히 버려지고, 호출은 성공으로 끝난다.** 실측(2026-09-06, 배포 번들에
`totally_bogus` 전달): 9개 도구 전부가 스키마에 `additionalProperties: false`를 광고하는데,
실제로 거부하는 것은 `grok_build_route` **하나뿐**이다(A1이 `.strict()`를 붙인 그 도구). 나머지 8개는
받아들이고 필드를 벗겨낸다. 값 수준 검증은 멀쩡하다 — `action`은 진짜 enum이고(`obliterate` 거부),
타입 불일치와 음수 `limit`도 거부된다. **미지의 키만 새어 나간다.**

실사용 피해를 끝까지 재봤다 — throwaway git repo에서 `worktreee`(e 3개)로 delegate 호출:

```
isError: false · status: completed · worktreePath: (없음) · filesChanged: ["typo-probe.txt"]
→ 격리를 요청했는데 grok이 사용자의 작업 디렉터리를 직접 고쳤고, 응답은 성공이라고 말한다
```

**안전 강등은 두 필드다.** `worktree`만이라고 적었다가 Grok이 반증했다 — `sandbox`도 같은
모양이다(오타 → `--sandbox` 미전달 → 프로파일 없이 실행). 확인 결과 `delegate.ts:391`이 실제로
플래그를 넘기고 Linux/macOS는 커널이 강제한다 — **지적이 맞다**. 나머지(`timeout_ms`·`model`·
`effort`·`resume`·`continue`)는 취향이 무시될 뿐 보호가 사라지지는 않는다.

→ 나머지 8개 등록에도 `.strict()`를 붙인다(A1이 route에 대해 이미 내린 결정과 같은 것).
  **오차단 위험은 실측했다:** MCP 스펙대로 `params._meta`에 실린 메타데이터는 strict인 route에서도
  통과하고, `arguments` 안에 잘못 넣은 경우만 거부된다. 즉 스펙을 지키는 클라이언트는 영향이 없다.

### A22. `redactSecrets`가 npm 토큰을 놓친다 (`history.ts`)

튜닝에 쓰지 않은 코퍼스로 재봤다(2026-09-06): 시크릿 18종 중 **16종 마스킹**, prose 12종 중
**0종 훼손**. 이전 라운드에서 Grok이 잡았던 과교정(`api_key: required` 류를 망가뜨리던 것)은 완전히
사라졌다. 새는 것은 `npm_...` 형태 하나다(`_authToken=npm_...`가 그대로 기록된다).

⚠️ 다른 하나(`ssh-rsa AAAA...`)는 **오탐이었다** — 공개키는 시크릿이 아니다. 시험 케이스가 틀렸다.

절대 원칙 #4가 "마스킹은 완화이지 보장이 아니다"라고 이미 못박고 있으므로 이것은 계약 위반이
아니라 **커버리지 한 칸**이다. 우선순위가 낮은 이유이고, 그래도 적어 두는 이유는 A6이 같은 종류를
같은 방식으로 닫았기 때문이다.

→ `npm_[A-Za-z0-9]{36}` 패턴 한 줄. prose 회귀는 위 코퍼스로 다시 잰다.
