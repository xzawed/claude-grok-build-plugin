# Grok plugin v0.2.3 — release notes

**Plugin version:** `0.2.3`  
**Previous GitHub Release:** `v0.1.0` (initial)  
**Audience:** people who install the `grok` plugin in Claude Code

---

## Summary

This is the **Grok starting point** release: Claude **orchestrates**, Grok **executes**, you **review**.  
It prefers your **subscription** (SuperGrok / X Premium+) billing path and **never auto-commits** after a delegation.

---

## Install / update

In Claude Code:

```
/plugin marketplace add xzawed/claude-grok-build-plugin
/plugin install grok@grok-marketplace
/reload-plugins
/grok:status
```

If you already installed it: **update** the marketplace/plugin, run **`/reload-plugins`**, then **`/grok:status`** and confirm `serverVersion` is `0.2.3`.

One-time prerequisites:

1. Grok CLI installed + `grok login` (subscription), or an API key in API mode  
2. **You** commit after review (the plugin never commits)

---

## What’s new (v0.1.0 → v0.2.3)

### Safe delegation (billing & auth)

- **Subscription by default:** API key env vars are stripped before spawning grok so metered billing does not leak in by accident.
- Every run reports **`billing`** (`subscription` / `metered_api`).
- Clear guidance when CLI is missing or you are not logged in; **PreToolUse auth hook** before delegate/plan/verify.
- **`/grok:status`:** readiness, expected billing, usage, and **`billingMismatch`** (subscription mode but history shows metered runs).

### Collaboration loop (Claude ↔ Grok)

| Step | Command / tool |
|------|----------------|
| Status | `/grok:status` |
| Who should do it | `/grok:route` → **`nextAction`** |
| Plan only | `/grok:plan` |
| Execute | `/grok:delegate` · `/grok:verify` |
| Review | `/grok:review` (no auto-commit) |
| Continue | `/grok:resume` (prior `sessionId`) |
| Usage | `/grok:usage` |

- Presets: `/grok:tests`, `/grok:migrate`, `/grok:boilerplate`
- Risky work: `worktree` isolation + `/grok:worktree` list/diff/apply
- First session: `/grok:tour` · `docs/08-getting-started-with-grok.md`

### Stability & platforms

- Native Windows CLI discovery and core delegate path (install via PowerShell `install.ps1`).
- CI on Linux + Windows, PreToolUse harness e2e, committed bundle tool-name checks.

---

## Things to know

1. **No auto-commit / auto-PR** — review the diff, then commit yourself.  
2. **If you see `billing: metered_api`** — a shell `XAI_API_KEY` may be winning over the session. Check `/grok:status` → `billingMismatch`.  
3. Prefer **`worktree: true`** for large or risky changes.  
4. Keep **security, architecture, and final review** with Claude/humans (`/grok:route` → `claude` means do not force Grok).
