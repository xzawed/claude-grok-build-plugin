**남아 있던 마지막 한 칸이 사람 몫이 아니었다.** B4는 "재시작한 세션이 이 번들을 로드하는가"를

결론은 Grok에게 반증시켰다(`CLAUDE.md` "5번 조리법", 5개 공격 → `CLAIM_SOUND`). 가장 날카로운

### v0.2.21 — 감사 큐 A7~A20 (큐가 비었다)

2026-09-05 감사가 연 20건 중 남아 있던 14건. 전부 배포 번들을 `.claude/tools/mcpcall.mjs`로

- **A7** hook의 subscription deny 분기가 **출하 구성에서만** 죽어 있었다. `.mcp.json`에 env가
  없어 `GROK_BUILD_AUTH_MODE`는 미설정이고, `resolveHookMode`는 그걸 `unknown`으로 읽었다 —
  그 분기를 짚는 테스트들이 전부 변수를 손으로 세팅해서 녹색이었던 것이 결함을 가렸다. 이제
  서버의 파서에 위임한다(정의를 하나로). 미설정 ALLOW→**DENY**, `Subscription`/` subscription `도
  마찬가지. 잘못된 값만 `unknown`으로 남는다 — 서버가 아예 못 뜨는 상태에서 "`grok login`을
  실행하세요"는 엉뚱한 안내다(A12).
- **A8** `worktree diff`가 한 응답 안에서 자기와 모순됐다(파일 3개 나열 + "1 file changed").
  `git diff`는 untracked를 못 보는데 그게 `--always-approve`의 주 산출물이다. 큐가 제안한
  `add -A`→`reset`은 창이 있는 **변형**이라 기각하고, `GIT_INDEX_FILE`로 worktree 밖 임시
  인덱스에 대고 같은 뷰를 만들었다 — 호출 전후 porcelain 바이트 동일. 테스트는 실제 git.
- **A9** 취소된 확인 프롬프트가 성공과 같은 모양이었다(`status ok`, exit 0). 유일한 근거가
  4000자 tail 안에서 잘릴 수 있는 산문이라, **잘리기 전 전체 출력**에서 판정해 `cancelled:true`로
  낸다. 두 마커를 모두 요구한다 — `sessions search cancelled`는 매칭 세션을 내고, `-y`로 응답된
  프롬프트도 같은 줄을 찍는다.
- **A10** `isError`가 양방향으로 틀렸다. `blocked`(spawn조차 안 됨)가 false로, api 모드 키 없는

  답한다 — blocked·cancelled는 true, 유효한 페이로드를 낸 읽기 전용 진단은 false.
  `grok_auth_check`는 **의도적으로** 그대로다(출력 전체가 판정이라 잃을 게 없다). 그 비대칭을
  테스트로 박았다.
- **A11** 한 단어 오타(`sesions`)가 60초를 태우고 읽을 수 없는 ANSI 프레임을 냈다 — 미지의 첫
  토큰은 grok에게 **프롬프트**이고 `-p` 없는 프롬프트는 TUI를 띄운다. `import`가 이미 그 이유로
  막혀 있던 것을 일반화. 20,729ms → **611ms**. allowlist라 낡는 방향이 반대여서, 슬롯이
  불확실하면 규칙이 물러서고 거부 문구가 "새 서브커맨드일 수 있다"고 직접 말한다.
