# v0.2.45 — `grok_auth_check`가 grok이 받지 않는 `auth.json`에 "준비됨"이라 하지 않는다(A56)

2026-10-23. A56은 2026-09-30 grok 1.0.44 재측정이 연 결함이다. 구독 모드의 인증 확인은 `auth.json`이 **있는지만**
본다 — 그 자체는 `docs/02` 정책 3·5가 정한 설계다. 그런데 grok이 받지 않는 파일에도 "준비됨"이라 말해, 확인하지 않은
것을 확인한 것처럼 불렀다. **메시지만 고쳤다 — `ok`와 게이트 동작은 그대로다.** 파일 내용을 읽거나 이력으로 not-ready를
정하는 것은 정책을 뒤집으므로 오너 판단으로 남긴다([`docs/09` §4.F](https://github.com/xzawed/claude-grok-build-plugin/blob/main/docs/09-scope-and-residuals.md)).
api 모드가 같은 이유로 A13에서 이미 그렇게 고쳤다 — present는 ok이되 "유효성은 검증하지 않았습니다"라 말한다.

| | 사용자에게 보이던 것 | 이제 |
|---|---|---|
| `grok_auth_check`·`/grok:status` (A56) | `GROK_HOME`의 `auth.json`이 `{}`·0바이트·잘린 파일·레거시 `<issuer>::<client_id>` 키 — grok이 거부하는 것 — 여도 `ok: true`에 "구독 세션 인증 준비됨."이라 했다. hook은 통과시키고, 위임은 2.5–4.7초 뒤 `auth_error`(올바르게 `grok login`을 말한다)로 끝났으며, 그 뒤에도 대시보드는 "준비됨"이었다 | `ok`는 그대로 `true`(파일이 있는지는 참이다)이되 메시지가 "구독 세션 파일이 있습니다 — 유효성은 검증하지 않았습니다."로 바뀐다 — 확인한 것(파일 존재)만 말한다. 없을 때의 `not_logged_in`·`grok login` 안내는 그대로다 |
| `commands/logout.md` | "every delegation is denied"(그때까지 모든 위임이 거절된다) | "delegations have no session to authenticate with and fail" — 레거시 항목이 남아 파일이 지워지지 않으면 게이트는 통과시키고 grok이 거부하므로, "거절"은 그 경우 틀렸다. "세션이 없어 실패한다"는 양쪽에서 참이다 |

## 재현 (쿼터 0 — grok 모델을 부르지 않는다)

배포 번들을 `.mcp.json`과 똑같이 stdio로 띄워(`node .claude/tools/mcpcall.mjs call grok_auth_check '{}'`), 격리한
`GROK_HOME`에 `auth.json` = `{}`를 두고 불렀다. `grok_auth_check`는 파일을 `stat`하고 PATH로 설치만 확인할 뿐 grok을
띄워 모델을 부르지 않는다 — 쿼터를 쓰지 않는다.

- 전(v0.2.44): `{ ok: true, mode: subscription, …, message: "구독 세션 인증 준비됨." }`
- 후(재빌드): `{ ok: true, mode: subscription, …, message: "구독 세션 파일이 있습니다 — 유효성은 검증하지 않았습니다." }`

0바이트·잘린 파일·레거시 키도 모두 같은 `existsSync` 경로라 같은 결과다(코드는 내용을 읽지 않는다).

## 고친 방법

- `mcp-server/src/auth.ts` `checkAuth`의 구독 파일-존재 분기 메시지 한 줄. `ok`와 다른 분기(미설치, 미로그인
  `grok login`, api 키 유무)는 건드리지 않는다. 주석에 A13 선례와 `docs/09` §4.F 경계를 적었다(번들에는 문자열만 바뀐다).
- `commands/logout.md`의 과장 문장.
- `mcp-server/test/auth.test.ts`에 A56 describe 블록(메시지가 `세션`·`검증`을 담고 `준비됨`을 담지 않음, `ok` 유지,
  미로그인 분기 유지)을 더하고, 기존 "subscription untouched" 테스트의 기대 문자열을 새 메시지로 바꿨다.
  `mcp-server/test/status.test.ts`의 `authOk` 픽스처 메시지도 새 문자열로.

## Grok과 함께

- 반증(5단계): 고친 `auth.ts`와 `auth.test.ts`를 빈 폴더에 그대로 떼어 주고 과다주장·회귀·테스트·범위 네 검사를
  정적 분석시켰다 — `VERDICT: FIX_SOUND`. 네 검사 모두 "none"이었고, `toContain('세션')` 단독은 옛 문구에도 맞지만
  `검증`·`준비됨` 금지·정확-문자열 단언이 함께 새 메시지를 못박는다는 점을 짚었다.
