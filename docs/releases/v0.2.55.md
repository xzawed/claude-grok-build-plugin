# v0.2.55 — grok 1.0.92에 맞춘다: grok_cli 기록이 grok이 보내는 질의를 남기고(A80·A81), 끝에 선 프롬프트 플래그를 돌리며(A82), 새 숨은 플래그 뒤로 새던 대화형 턴을 막는다(A83)

grok CLI가 이 머신에서 1.0.70에서 1.0.92로 올라왔다(2026-11-28, `grok_cli ["update"]`). `npm run probe:contract`가 드리프트를 보였고
(보이는 플래그 셋이 늘고 도움말 본문 68쪽 중 59쪽이 바뀌었다), 플러그인이 기대는 문장을 쿼터 0으로 다시 쟀다. 처음 잰 모양에서는
인증·과금 게이트의 구멍이 없었지만, 머지 전 검토가 1.0.92의 새 숨은 플래그 뒤로 인증 확인도 기록도 없이 도는 대화형 턴을 찾았다
(A83 — 1.0.92의 숨은 플래그를 분류하고, 표에 없는 플래그 뒤의 규칙을 닫힌 쪽으로 고쳐 닫았다). 결함 넷(A80–A83)을 고치고, 새
플래그(보이는 값 플래그 하나와 숨은 플래그들 — 목록은 계약 §16)를 분류하고, Claude에게 보이는 `grok_cli` 설명과 거부 안내, 계약 문서를
1.0.92의 사실로 바꾼다.
MCP 2.0 계획(`docs/plans/2026-11-28-mcp-v2-dual-protocol-plan.md`)의 1번 PR이다 — 그 재검증은 1.0.92를 기준으로 한다.

## 재현 (쿼터 0 — win32, grok 1.0.92)

배포 번들을 `.claude/tools/mcpcall.mjs`로 몰고, grok은 합성 세션(`scripts/synthetic-auth.mjs`)·버릴 `HOME`·`USERPROFILE`·
`GROK_HOME`·`CLAUDE_CONFIG_DIR`(위임 이력 파일도 그 홈의 것)에서, 두 API URL을 404를 답하는 루프백으로 돌렸다. grok이 보낸 사용자
질의는 루프백이 받은 POST 본문에서 읽었다.

## 무엇이 바뀌었나 (grok 1.0.70 → 1.0.92, 플러그인이 기대는 것만)

측정과 원문은 `docs/specs/grok-cli-contract.md` §16 끝 "1.0.92 재측정"이 원천이다.

- **프롬프트 플래그와 위치 인자를 이어 붙인다** — 1.0.70까지는 함께 쓰면 exit 2였다. 1.0.92는 플래그의 값과 모든 위치 인자(`--` 뒤도)를
  명령줄 순서대로 공백 하나로 이어 보낸다. 플러그인은 두 모양 모두 인증 게이트에 걸었지만, 이력에는 플래그의 값만 남겼다 → **A80**.
- **`-p, --single [<PROMPT>]`** — 값이 선택이 됐다. 다음 토큰은 서브커맨드 이름이어도 값이지만(`-p sessions`가 "sessions"를 보냈다)
  `-`로 시작하면 값이 아니다(`-` 하나는 stdin이라 값이다): `-p --help`는 도움말을 찍고 끝났고 `-p --always-approve Say`는 "Say"를
  보냈다 — 1.0.70은 둘 다 "*a value is required*"(exit 2)였다. 값이 없고 단어도 없으면 stdin에서 읽는데 `grok_cli`는 stdin을 주지
  않아 "*prompt is empty*"(exit 1, 요청 0)로 끝난다. 플래그가 인자를 끝내고 앞에 단어가 있으면 그 단어가 프롬프트다(`Say -p`는
  "Say"를 헤드리스로 보냈다). 기록은 그 토큰을 값으로 읽었고(**A80**·**A81**), 거부 규칙은 끝에 선 플래그 앞의 단어를 맨 단어로
  읽었다(**A82**).
- **`[PROMPT]...`** — 맨 단어 뒤의 단어는 서브커맨드 이름까지 프롬프트가 되어 대화형 UI가 모델에 보냈다(`hello world`·`fixword version`).
  플러그인은 맨 단어를 이미 거부한다(A52). 하지만 표에 없는 플래그 뒤에서 오른쪽에 서브커맨드 이름이 보이면 물러나던 규칙(1.0.44에서는
  그 서브커맨드가 돌았다)이 이것으로 구멍이 됐다 → **A83**. 설명과 거부 안내의 "뒤에 단어가 붙으면 exit 2"도 거짓이 됐다. 예외 하나:
  프롬프트 플래그의 값 뒤 첫 위치 인자가 서브커맨드면 grok이 거절한다(`-p x version` → "*`version` is a grok command, so it would run
  and drop the prompt*", exit 2, 요청 0).
- **숨은 플래그** — 1.0.92는 도움말에 없는 플래그를 여럿 더했다(1.0.70은 모두 "*unexpected argument*"): `--cwd`의 별칭
  `--workspace`를 포함한 값 플래그들과 여러 스위치. clap에게 직접 가르게 한 방법(바이너리의 `--이름` 철자, `grok completions bash`가
  적는 표준 이름, 이름 바로 뒤에 구분자 없이 붙어 저장된 별칭)과 목록은 계약 §16이 원천이다. 1.0.70의 `-e`는 사라졌다.
- **`--system-prompt-file <PATH>`**(새 값 플래그), **`--memory-flush`·`--no-memory`**(이제 도움말에 보인다 — 이미 분류돼 있었다),
  **`usage`**(세션 id 생략 가능 — 이 머신에서는 "*can't show your plan's usage here yet*", exit 1, 남은 프로세스 없음),
  **`sessions list --all`**(새 불리언).

## 고친 것

1. **A80 — `grok_cli`의 위임 이력이 grok이 보내는 프롬프트를 남긴다.** `server.ts`의 기록이 `extractPromptRun(args)?.prompt` 대신
   `promptGrokSends(args)`(`grok-cli.ts`)를 쓴다: 프롬프트 플래그의 값과, 그 플래그·값을 뺀 나머지 위치 인자를 명령줄 순서대로 잇는다.
   `--prompt-file`·`--prompt-json`은 지금처럼 파일 이름을 남기고, `--` 뒤에서 찾은 플래그는 글자라 예전처럼 읽는다. 이를 위해
   `extractPromptRun`(leaf 모듈 `prompt-flags.ts`)이 플래그 토큰과 값 토큰의 위치, 파일 형태 여부를 함께 돌려준다 — 게이트(`mayRunTurn`)의
   판정은 바뀌지 않는다. 빈 값(`--single=`)은 단어로 넣지 않는다 — `--single= Say`는 "Say"를 보냈다. 프롬프트 플래그가 `-`로
   시작하는 떨어진 토큰을 받지 않는 1.0.92의 규칙은 `promptFlagTakes`(`prompt-flags.ts`)다: 그때 `extractPromptRun`은 `prompt: ''`·
   `valueAt: at`을 돌려주고, 결과가 여전히 정의되므로 인증 훅(`mayRunTurn`)은 지금처럼 게이트를 건다. `--` 바로 앞의 프롬프트 플래그는
   거부 규칙 셋이 전체 인자에서 위치로 읽는다(`promptFlagBeforeSeparator`) — 이 수정의 첫 빌드는 `--` 앞만 읽어 `-p -- Say`를 맨
   단어로 거부했다(그 번들에서 "blocked"로 실측; v0.2.54는 실행했다). 미리보기는 원래 인자를 한 번만 읽어 각 위치 인자의 자리로
   고른다 — 플래그 토큰을 빼고 다시 읽던 첫 판은 `-w`·`-r`(선택 값)이 다음 단어를 삼켜 `-w -p Fix it`을 "Fix"로 남겼다(머지 전 검토;
   git 저장소에서 grok은 "Fix it"을 보냈다). 표에 없는 플래그를 지나서는 어떤 플래그도 받을 수 없는 것 — 프롬프트 플래그의 값과 `--`
   뒤의 단어 — 만 남긴다. 그런 플래그는 뒤의 단어를 하나 이상 값으로 받을 수 있어, 잇기가 그 값을 이력에 적었다(`--modle grok-4 -p Fix`
   — grok 1.0.92가 "*unexpected argument*"로 끝내는 오타 — 를 이 PR의 앞 판 번들은 "grok-4 Fix"로, v0.2.54는 "Fix"로 남겼다; 지금은
   "Fix"). 그래서 이력이 grok이 보낸 단어를 빠뜨릴 수는 있어도, 보내지 않은 단어를 적지는 않는다. `--print`(--single의 숨은 별칭)는 그래서
   파스의 프롬프트 플래그 표(`PROMPT_VALUE_FLAGS`)에도 넣었다 — 모르는 플래그로 남으면 그 뒤의 단어가 잘린다.
2. **A81 — 출력만 하고 끝나는 실행은 프롬프트 실행이 아니다.** `-vp x y`는 버전을 찍고 exit 0으로 끝났는데(요청 0) `grok_cli`가 이를
   프롬프트 실행으로 읽어 일어나지 않은 위임을 "완료"로 기록했다(v0.2.54 번들에서 재현 — 도움말·버전이 옆 토큰과 상관없이 찍고
   끝나는 것은 1.0.44부터 잰 동작이다, 계약 §16). `-p --help`·`--single --version`·`-cp --help`도 1.0.92에서 같은 꼴이 됐다.
   `runGrokCli`가 먼저 `parseGrokArgs`의 `printsAndExits`를 보고, 그렇다면 git도 돌리지 않고 기록도 하지 않는다 — `parseGrokArgs`는
   `-p`·`--single`을 같은 규칙으로 읽어(`PROMPT_VALUE_FLAGS`) 그 뒤의 도움말·버전 플래그를 본다. 인증 훅은 지금처럼 그런 실행에도
   게이트를 건다(과잉 게이트, 해가 없다).
3. **A82 — 끝에 선 프롬프트 플래그의 실행을 거부하지 않는다.** `Say -p`·`Say --single`·`Say --print`·`Say ok. -p`·`--memory-flush
   Say -p`는 1.0.92에서 헤드리스로 그 단어를 보내는데(1.0.70은 "*a value is required*", exit 2) `grok_cli`는 앞의 단어를 대화형 UI의
   맨 단어 프롬프트로 읽어 spawn 없이 거부했다(v0.2.54 번들에서 넷 모두 "blocked"). Grok 반증 2회차가 UNKNOWN으로 둔 행을 재서
   찾았다. `trailingPromptFlag`(`prompt-flags.ts`)가 인자를 끝내는 프롬프트 플래그를 찾고 `mayRunTurn`이 그것도 세어, 인증 훅이
   `Say --single`·`Say --print`를 막는다 — 고치기 전 훅 번들은 auth.json 없이도 둘을 통과시켰다(서버만 고쳤다면 인증 확인 없이
   턴이 돌았다). `promptRunOf`(`grok-cli.ts`)는 첫 위치 인자가 프롬프트 단어일 때만 그 플래그를 프롬프트 실행으로 읽고, 거부 규칙·
   기록·미리보기가 같은 판단을 쓴다. 단어가 없거나(`-p`·`--single` 단독, `--memory-flush -p`), 서브커맨드 뒤거나(`sessions search
   -p`), `--` 뒤이거나, 표에 없는 플래그 뒤면 예전과 같다.
4. **A83 — 새 숨은 플래그 뒤로 새던 대화형 턴을 막는다.** `--new-session-id <uuid> Say sessions`·`-H 'X-A: b' Say sessions`·`--plan
   Say sessions`는 1.0.92에서 대화형 UI가 "Say sessions"를 모델에 보내는데, 래퍼는 그 플래그를 몰라 "오른쪽에 아는 서브커맨드가 있으니
   프롬프트 실행이 아니다"로 물러나 spawn했다 — 인증 훅도 막지 않고(`mayRunTurn`이 false) 위임 이력도 남지 않았다(v0.2.54 번들과 이
   PR의 첫 판 모두 재현). 머지 전 검토가 찾았다. 두 가지로 닫았다: ① 1.0.92의 숨은 플래그를 `grok-cli.ts` 표에 분류하고(목록은 계약
   §16; `-f`는 `prompt-flags.ts`의 `BOOLEAN_SHORTS`에도 — `-fp Say`가 `-f -p Say`로 읽혀 실행·기록된다; 짧은 값 플래그 `-H`는 숨은
   값 플래그 표로 읽는다), 훅의 `runFolder`가 `--workspace`를 `--cwd`처럼 읽는다 ② 표에 없는 플래그가 첫 단어 앞에 있으면 거부한다 —
   그 플래그가 값을 받는지에 따라 grok이 읽는 첫 단어와 프롬프트가 갈리기 때문이다. 처음에는 두 읽기를 모두 흉내 내 프롬프트 단어가
   남지 않을 때만 물러나게 했는데, 검토가 돌 때마다 새 구멍을 찾았다(표에 없는 플래그 둘, 묶음 안 스위치 뒤의 값 글자, `--` 앞에 남는
   단어가 없는 경우) — 그래서 흉내를 그만두고 분류될 때까지 거부한다. 1.0.92에는 그런 플래그가 없다(계약 §16).
5. **`--system-prompt-file`을 `VALUE_FLAGS`에 넣었다** — 값(경로)을 위치 인자로 읽지 않는다.
6. **설명·안내·주석** — Claude에게 보이는 `grok_cli` 설명의 맨 단어 문장과 맨 단어 거부 안내(“뒤에 인자가 더 있으면 오류”가 1.0.92에서
   거짓), `commands/cli.md`·`docs/04`·`hooks/hooks.json`의 같은 문장, `grok-cli.ts`·`prompt-flags.ts`·`hook.ts`의 주석(A2·A11·A52·A63
   근처)을 1.0.92의 실측으로 바꿨다. 계약 문서는 머리의 측정 이력, §16 끝 "1.0.92 재측정"과 유효 버전 표, §1의 `-p` 줄;
   `scripts/contract-snapshot.json`은 1.0.92로 다시 받았다.

## 하지 않는 것

- **`--memory-flush` 거부(A63)는 그대로다** — 1.0.92에서 이어 갈 세션이 있는 `-c`/`-r --memory-flush`는 재지 않았다. 프롬프트 플래그와
  함께면 지금처럼 게이트를 거친다.
- **`usage`의 분류는 그대로다** — 세션 id 없이도 호출이 끝난 뒤 남는 프로세스가 없었다(실측). 요금제 한도를 헤드리스로 읽는 일은
  1.0.92에서 아직 되지 않는다.
- **인증 게이트는 넓어지기만 했다** — 판정이 바뀐 것은 인자를 끝내는 `--single`·`--print`뿐이다(더 막는 쪽: 단어 없이 홀로
  쓰면 턴이 돌지 않는데도 이제 훅이 막는다 — 서버도 어차피 거부하는 실행이다). A83의 턴은 게이트가 아니라 거부 규칙으로 막았다.
- **`-p`·`--single` 단독은 지금처럼 spawn 없이 거부한다** — 1.0.92에서는 "*prompt is empty*"로 끝날 실행이라 해가 없다.
- **표에 없는 플래그가 첫 단어 앞에 있으면 거부한다(A83의 값)** — `F sessions list`처럼 서브커맨드로 끝날 실행도, `F`를 이 래퍼가
  모르면 거부한다(값 플래그라면 `list`가 프롬프트가 된다). grok이 새 플래그를 더하면 분류될 때까지 그런 실행은 터미널에서 직접 해야
  한다 — 인증 확인 없이 턴을 내보내는 쪽보다 낫다. 1.0.92의 플래그는 모두 분류돼 있어 지금은 해당하는 실행이 없다.
- **`-p x <서브커맨드>`는 기록이 남는다** — grok이 exit 2로 거절하는 실행이라(위 "무엇이 바뀌었나") 그 행은 실패한 위임의 행이다.
