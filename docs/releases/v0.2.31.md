# v0.2.31 — 못 잰다고 적어둔 것을 재러 갔더니, 결함은 우리 쪽에 있었다

2026-09-23. `docs/10`의 **B4**는 "리눅스 또는 macOS 머신이 있어야 잰다"로 닫혀 있었다. 이 레포는
win32에서 돌고, 샌드박스 커널 강제는 Linux Landlock / macOS Seatbelt뿐이기 때문이다.
**Docker가 그 머신이다.** 그리고 결함은 리눅스 커널이 아니라 **우리가 쓰는 문장**에 있었다.

| 잰 것 | 답 |
|---|---|
| `GROK_SANDBOX`가 요청하지 않은 위임을 바꾸는가 | **그렇다** (4-arm 통제/처리로 확정) |
| 조용히 제약하는가 | **아니다 — 큰소리로 거부한다** (fail-closed, 인증 전이라 과금 없음) |
| 래퍼는 그 거부를 뭐라고 보고했나 | **"Grok Build 출력을 해석할 수 없습니다"** ← A33 |
| 샌드박스가 정상 작동할 때 응답은 | **아무 말도 하지 않는다** (네 응답이 바이트 동일) |
| 인증된 턴에서 쓰기가 실제로 막히는가 | **아직 못 쟀다** — 실계정 필요, B4에 남겨둠 |

---

## A33 — 확인한 적 없는 원인을 단정했다

grok 1.0.41은 샌드박스를 적용할 수 없으면 시작 자체를 거부한다:
`Refusing to start with denied paths unprotected.` — exit 1, stdout 0바이트. **좋은 동작이다.**
그런데 stdout이 비어 있으니 래퍼의 "envelope 없음" 분기로 떨어지고, 그 분기는 원인을
**"출력을 해석할 수 없습니다"** 라고 말해왔다. 서로 다른 세 실패(bwrap 부재 / namespace 거부 /
프로파일 미정의)에 같은 문장이 나갔고, 셋 다 그 문장과 무관하다.

`b721433`(릴리스 게이트)과 같은 모양이다 — **멈춘 건 옳고 사유가 틀렸다.**

이 경로가 하필 중요한 이유는 `--sandbox`에 **env 별칭**이 있기 때문이다
(`[env: GROK_SANDBOX=]`). 호출자가 아무것도 넘기지 않아도 오퍼레이터 셸의 변수 하나가 위임을
죽인다. 그리고 그 변수는 **호출자가 보낸 요청 어디에도 없다** — "출력을 해석할 수 없습니다"에서
거기까지 갈 방법이 없다.

이제 메시지가 변수를 지목하고 `sandbox: "off"`를 안내한다. 일반 분기는 원인을 단정하지 않고
`rawStderrTail`을 가리킨다.

## Grok이 이 수정 안에서 같은 결함을 찾았다

초판 신호는 `/^bwrap: /im`이었다. `m`은 `^`를 **모든 줄 머리**에 붙인다 — grok이 작업 중 스스로
`bwrap ...`을 실행하고 그 stderr가 섞이면 "grok이 시작을 거부했다"로 보고된다. grok은 시작했고,
실패한 건 사용자의 명령이다. **A33이 고치려던 오류를 A33의 수정 안에 다시 심을 뻔했다.**

전체 stderr 머리로 앵커를 옮겼다. 앞에 다른 출력이 있으면 일반 메시지로 떨어지고, 그쪽은 아무
원인도 주장하지 않는다 — **실패하려면 그 방향으로 실패해야 한다.**

⚠️ **리뷰 프롬프트에 대해 하나 배웠다.** "반례를 발명하라"는 두 번 다 180초 타임아웃했다.
같은 질문을 **내가 쓴 후보 4개를 분류하라**로 바꾸니 한 번에 돌아왔고 그 답이 위 오탐이다.
`CLAUDE.md` §5의 "한 번에 한 가지 주장만"에 더해 — **개방형 생성 과제를 주지 말 것.**

## 하네스가 여섯 번 틀렸다 (진짜 결함 2건 대비)

2026-09-12에 기록한 비율이 그대로 재현됐다. 전부 출력이 명백히 이상해서 잡혔다 — 그럴듯하게
틀렸다면 그대로 보고됐을 것이다. 목록은 `CHANGELOG.md`가 원천이고, 그중 둘만 옮겨 적는다.

**통제군이 없었으면 결론이 뒤집혔을 둘:**

- 자격증명 없이 재려 했더니 서버의 **spawn 전 인증 게이트**가 네 arm을 동일하게 막았다.
- 합성 `auth.json`을 한 번만 썼는데 **grok이 401 후 그것을 폐기**해서(계약 §7 C) arm 2~4가 다시
  게이트로 떨어졌다.

둘 다 **"샌드박스는 차이를 만들지 않는다"** 라는 그럴듯한 답을 냈다. Grok이 설계 검토에서
경고한 교란("세션 사유 실패와 샌드박스 차단이 구분 불가")이 정확히 그대로 일어난 것이다.
통제군은 형식이 아니다.
