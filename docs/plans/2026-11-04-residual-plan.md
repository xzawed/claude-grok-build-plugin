# Plan: 남은 작업 — 권장안과 권장 순서 (2026-11-04부터)

> **열린 계획 — 2026-11-04 작성.** 오너 지시(원문): "잔여 작업을 Grok과 함께 논의하여 권장안 과 권장순서 기준으로 이행 부탁드립니다".
> Grok은 그날 두 번 모두 HTTP 402(*Grok Build usage balance exhausted*)로 끝나 논의하지 못했고, 오너는 선택지 "지금 착수, Grok은
> 나중에 (권장)"을 골랐다 — 측정을 반영한 유지보수자의 권장안으로 착수하고, Grok과의 2라운드 논의(서로 목록을 고정한 뒤 비판)와 각
> 수정의 5단계 반증은 사용량이 돌아오면 한다. 같은 날 오너는 1번의 머지를 승인하며 Grok 검토를 사용량이 돌아올 때까지 보류했다 —
> 그동안의 묶음은 Grok 없이 머지를 묻고, 돌아오면 나간 묶음부터 반증한다. 논의가 아래를 바꾸면 이 문서를 먼저 고친다.
> 결함의 사실은 `docs/10`, grok 쪽 사실은 계약(`docs/specs/grok-cli-contract.md`), 판단의 원천은 `docs/09` §4다 — 여기는 순서와 방법의
> 권고만 둔다. 묶음이 나가면 "나간 것"에 적고, 다 나가거나 버려지면 머리를 "SHIPPED — 이력 문서. 실행하지 말 것."으로 바꾼다.

**나간 것:** 1번(v0.2.52), 2번(v0.2.53), 2b(v0.2.54), 3번(유지보수 도구라 릴리스 없음 — 만점 채점은 v0.2.52 대신 그때의 최신 v0.2.54로
쟀다; 옛 번들은 v0.1.0도 더 쟀다), 4번(문서만 — `docs/09` §4 F의 세 행). 2b는 2와 함께 가지 않았다 — 모든 도구가 쓰는 작업 폴더 확인을 바꾸고 win32에서 따로 재야 해서 작지
않다고 봤다.
