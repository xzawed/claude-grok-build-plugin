# Grok plugin v0.2.11 — release notes

**Plugin version:** `0.2.11`
**Previous release:** `v0.2.10`
**Severity:** One regression introduced by v0.2.10, plus the half of v0.2.10's leak fix that did
not actually work. Auth, the subscription env strip, `--always-approve` and no-auto-commit are
unchanged.

---

## Summary

A re-audit of v0.2.9 / v0.2.10 — six parallel dimensions, adversarially verified, cross-checked
with Grok Build — found that v0.2.9 held up under every attack, and that v0.2.10 broke one thing
and left another unfinished.

The re-audit's other result is worth stating: measured against the pre-audit tree with the same
14 SonarSource rules, the +271 lines added by v0.2.9 and v0.2.10 introduced **zero** new rule
violations, and line coverage moved 75.62% → 78.09% with branch coverage crossing the 80% gate.

---

## The regression

**v0.2.10 routed every git call through one 30-second budget, but `git worktree add` is a full
checkout of HEAD.** Before v0.2.10 that call was unbounded. Measured with the shipped default: a
20,000-file repo was SIGTERM-killed at 87% (17,400 files), and a 6,000-file repo already spent
31–61% of the budget. Every killed attempt left a partial checkout directory, a
`.git/worktrees/<name>` registration and a `grok/<name>` branch behind — so the release that
existed to stop leaks created a new one — and `runDelegate` reported the wrong cause ("check that
cwd is a git repo with commits").

- Checkout-sized work now has its own budget, `GIT_BULK_TIMEOUT_MS` (10 minutes): `worktree add`
  and `worktree remove --force`. Metadata reads keep the 30-second one. Both are still finite, so
  a wedged git still cannot hang the server forever.
- A failed `worktree add` now cleans up all three leftovers before rethrowing. Nothing has run
  inside the tree at that point, so discarding them is safe.
- The delegate error now carries the real cause instead of guessing at the repo state.

## The unfinished half

**`prune` could only ever remove worktrees registered to the repo it was called from.**
`~/.grok-build/worktrees` is global; `git worktree remove` is per repo. Measured on the author's
machine: 36 trees spanning three different repos — 34 from one project, one from another, one from
a scratch repo — so pruning from any single project reclaimed almost nothing and reported the rest
as failures.

- Each candidate's owning repo is now read from its `.git` file (a linked worktree's `.git` is a
  file containing `gitdir: <repo>/.git/worktrees/<name>`), and removal runs there.
- A tree git no longer knows — owner gone, never registered, registration already pruned — is
  deleted directly after re-confirming the path still resolves inside the base dir, and reported
  in `removedOrphan`. If an owner is known, its stale registration is pruned too.

## The safety hole in prune

`prune`'s age is the worktree directory's own mtime, which **never changes when a nested file is
edited** — verified independently twice. So "old" meant "created long ago", not "unused", and
`apply` would have force-deleted a tree still holding grok work that was never applied, taking its
branch with it.

- The field is now named `createdDaysAgo` and says what it measures.
- `apply` **never deletes a tree with uncommitted changes**; those are reported in `skippedDirty`.
  To remove one anyway, use `action: "remove"` on it explicitly, after reviewing `action: "diff"`.
- The dry-run message says how many candidates are protected this way.

---

## Not changed, deliberately

The re-audit cleared the rest: prune cannot escape the base dir (junction, `..`, absolute name and
a TOCTOU swap were all probed and refused), the `grok/<name>` branch argument cannot be read as a
git flag, `appendBounded` genuinely prevents the OOM it was added for (2 GB fed through a 256 MB
heap stayed at 5.3 MB), and the new `--name-only -z` change to `filesChanged` is strictly better
than the old `+++ b/` scrape — which was silently empty for binary-only, mode-only, deleted and
renamed files.

The four SonarSource rule findings (two cognitive-complexity, one collapsible if, one nested
ternary) all predate the audit and remain out of scope, as does the coverage gap to 80%.

## Tests

`npm test` 259 → 270 (`npm test` is the SSOT for the count).

## How to update

Marketplace update/reinstall → `/reload-plugins` → `claude plugin list` enabled →
`/grok:status` `serverVersion` **0.2.11**. Cache is version-keyed; do not reuse 0.2.10.
