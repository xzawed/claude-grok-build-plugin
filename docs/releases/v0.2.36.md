# v0.2.36 — 전체 감사가 찾은 결함 12건 (A37~A48)

2026-09-25. 오너가 요청한 전체 감사(코드·문서, 로컬 SonarQube 서버 + Grok)에서 **두 가지 이상의 독립 방법으로
다시 잰** 결함 12건을 고쳤다. 오너가 "확인된 결함 모두를 Grok과 함께"로 착수를 맡겼다. SonarQube가 준 신뢰성 D·보안 C는
오탐과 설계상 선택이 만든 등급이었고(서버·eslint-plugin-sonarjs·Grok 분류·소스 판독이 일치), 아래 결함은 그 등급 밖에 있었다.

| # | 사용자에게 보이던 것 | 이제 |
|---|---|---|
| A37 | `DB_PASSWORD=`·`JWT_SECRET=`·`SECRET_KEY=`·`"DB_PASSWORD":` 같은 `.env` 형태 **9/9**가 위임 이력에 그대로 남고 usage/status로 Claude에게 되돌아갔다 | 이름의 마지막 성분으로 판단한다 — 9/9 가림 |
| A38 | bare repo·서브모듈에 붙은 worktree는 상태 확인이 한 번 실패하면 `prune`을 `apply: true`로 돌릴 때 **미적용 grok 결과물을 삭제**했다 | 소유 저장소를 모든 레이아웃에서 읽고, 못 읽으면 판단을 보류한다(보호) |
| A39 | Windows에서 약 32K자가 넘는 위임이 `"spawn ENAMETOOLONG"` 한 줄로 실패했다 — 모드·과금·이력 없이 | argv가 싣지 못하는 프롬프트만 비공개 임시 파일로 `--prompt-file`; 시작 실패는 구조화된 오류 |
| A40 | 이력 한 줄의 `cwd`가 문자열이 아니면 `cwd`를 준 `status`·`usage`가 매번 실패했다 | 그 줄은 디렉터리 일치가 아닐 뿐이고, 요약은 계속된다 |
| A41 | 손자 프로세스가 grok의 파이프를 쥐면 2초 캡이 8.1초까지 늘었고 정상 종료가 `timedOut`이 됐다 | grok이 끝난(또는 캡이 터진) 뒤 `EXIT_GRACE_MS` 안에 끝난다 |

| A44 | 영어 "token"은 보안 신호가 아니었다(한국어 "토큰"은 맞다) — 세션 토큰 작업이 LOW로 무인 위임됐다; "1 file"이 대량 작업이었다 | 둘 다 고쳤다 |
| A45 | 작업 트리 쪽 리네임(` R b.txt\0a.txt\0`)이 `filesChanged`에 가짜 경로(`xt`)를 넣었다 | 두 번째 상태 칸도 본다; 복제돼 있던 파서 둘을 하나로 |
| A46 | `timeout_ms: 3e9`는 1ms 타이머가 됐다 — grok이 21ms에 timeout | 스키마가 거절하고, 타이머도 잘라 쓴다 |
| A47 | PreToolUse hook이 호출마다 grok 설치를 **두 번** 확인했다(각각 5초 상한의 프로세스) | 한 번 |
| A48 | "비인증" probe가 API 키 둘만 지워, 토큰 제공자 env가 있으면 실제 과금 턴이 될 수 있었다; POSIX에서는 캡이 grok을 죽이지 못했다 | `throwawayHomeEnv`(GROK_*·XAI_* 전부 제거) + `detached` |

머지 전 검토가 이 릴리스의 수정이 만든 회귀와, 같은 약속 안에 있던 기존 결함 셋을 더 찾았다 — 아래 "머지 전 검토".

## 무엇이 바뀌나

- **A37 (`history.ts`):** `name =`/`name:`은 모두 후보이고 **이름이 결정한다**. `_ . -`와 camelCase로 나눈 마지막
  성분이 자격증명 단어인지 본다: password·secret·token·passphrase·`accesskey` 같은 붙여 쓴 키, 앞에 무엇이 붙은
  긴 단어(`PGPASSWORD`), 뒤의 숫자 성분(`DB_PASSWORD_2`), 한정된 `key`(api·access·secret·private·encryption·signing·
  account·master·hmac). 등급은 **잎**(마지막 `.` 뒤, 앞의 `-` 없이)이 정한다 — `process.env.GITHUB_TOKEN`도 이름 붙은 키다.
  이름 붙은 키와 환경 변수 모양(UPPER_SNAKE) 이름은 그 자체로 증거라 값이 그럴듯하기만 하면 가리고, 코드·산문 모양의
  이름은 여전히 불투명한 값이어야 한다. 남기는 것: **안에 든 것이 이름인** 자리표시(`<your_key>`·`${X}`·`$X`·`%X%`·
  `your-…`·`changeme` — `$uperS3cretPassw0rd` 같은 불투명한 값은 가린다), 기본값이 없는 셸 참조(`${X:-hunter2}`는
  기본값으로 판단한다), 세는 단어(`token`·`pass`) 뒤의 숫자 설정(`MAX_OUTPUT_TOKEN=128000`), 플래그·타입(`yes`·
  `enabled`·`SecretStr`), 인용 없는 호출·인덱스 모양 코드(`z.string().min(32)`), 빈 값 다음 줄의 대입. 인용 없는 값을
  둘러싼 닫는 문자(`)`·`]`·백틱·마침표·`;`)는 가림 밖에 남긴다. 후보는 **구분자에서 끝나고** 값은 자격증명 이름일
  때만, **가리든 않든 한 번** 읽고 지나간다 — 그래서 `$env:DB_PASSWORD=`는 `env:` 뒤에서 찾히고 `k=k=k…`·`pwd=${…`도
  선형이다.
- **A38 (`worktree.ts`):** 소유자는 마지막 `/worktrees/<name>` 앞(끝의 `/.git`은 뗀다) — bare(`proj.git`·`.bare`),
  서브모듈(`.git/modules/<sub>`), git 2.48의 상대 gitdir까지. 상대 gitdir는 git처럼 트리의 **실제 경로**에서 푼다(기준
  폴더가 심볼릭 링크·정션 너머여도). **읽지 못한 소유자는 "사라짐"이 아니라 "모름"**이고 모름은 보호된다. 소유자가
  정말 없으면(A5의 고아) 여전히 거둔다.
- **A39·A41·A46 (`delegate.ts`):** `defaultSpawn`은 `spawnBounded('grok', …)`가 됐다 — 동기 예외와 파이프 없는
  자식(파일 서술자가 바닥났을 때, EMFILE)을 `spawnError`로, grok의 `exit`에서 캡을 멈추고 `EXIT_GRACE_MS` 유예 뒤
  (POSIX는 그룹을 거두고) 파이프를 놓는다. 유예는 캡에서도 시작해 **kill이 실패해도** 호출이 끝난다. 실패한 kill은
  더는 "시작 실패"로 읽히지 않는다. `--prompt-file`은 argv가 싣지 못하는 프롬프트에만 쓴다 — 한도는 `promptFitsArgv`가
  플랫폼별로 정한다(win32는 명령줄의 UTF-16 단위를 인용이 두 배로 늘리는 최악을 두고, POSIX는 인자 하나의 바이트를
  센다). 파일은 비공개 `mkdtemp` 폴더에 쓰고(POSIX에서 0600) `finally`에서 지운다. 네 도구의 `timeout_ms`는
  2147483647이 상한이다.
- **A40 (`usage.ts`):** 문자열이 아닌 `cwd`는 디렉터리 일치가 아니고, 문자열이 아닌 `ts`는 첫/마지막 시각에 들지 않는다
  (`{"toString":0}`처럼 변환할 수 없는 값도).
- **A42 (`delegate.ts`):** plan의 두 반환 경로가 `finish`를 탄다(B1·B3). HEAD가 움직이면 `committed: true`이자 쓰기이고,
  메시지는 `git status`가 아니라 `git show HEAD`를 가리킨다(`/grok:plan`이 그 메시지를 보여준다). 지문에 untracked 파일
  **내용**을 넣었다 — 목록 앞쪽 `UNTRACKED_HASH_MAX_FILES`개를 32개씩 병렬로, 32 MiB까지(그 뒤는 크기·수정 시각).
  porcelain 경로는 저장소 루트 기준이므로 `--show-toplevel`에서 읽는다(줄 끝만 떼고 — 폴더 이름 끝의 공백은 이름이다).
- **A43:** 라우팅 넷·`normalizeCwd`·`semverOf`는 Grok이, 가림 셋(URL은 `://`에 고정, JWT는 base64url 덩어리 단위
  스캐너, PEM 블록은 다음 BEGIN에서 멈춤)은 A37과 함께. `s3 rm … --recursive`는 정규식이 아니라 줄 단위로 본다.
- **A44 (`routing.ts`):** "2개 이상의 파일"은 `1,000`·`1.000`·`1 000`처럼 적은 수도 읽는다. 단수 `token`(`refreshToken`
  안도)은 세거나 쪼개는 뜻(`max token`, `token count`, `tokenizer`)이 아니면 보안 신호이고, 복수 `tokens`은 누구의 것인지
  말할 때(`api tokens`, `refresh_tokens`)만이다.
- **A45 (`git-porcelain.ts`, 새 리프 모듈):** `delegate.ts`·`worktree.ts`의 바이트 동일 사본을 하나로 — 결함을 두 번
  고쳐야 했던 이유를 없앴다. untracked 경로 판독도 여기(A42가 쓴다).
- **A47·A48:** hook의 설치 확인 한 번, probe의 `throwawayHomeEnv`(새로 `synthetic-auth.mjs`에) + `detached`.

## 전후 실측

- **감사 페이로드를 같은 입력으로 다시 쟀다.**
  - 재빌드한 배포 번들 e2e(쿼터 0 — 임시 홈, 합성 세션, `node.exe` 사본을 `grok.exe`로):
    - A40 — `cwd`를 준 `usage`·`status`: `isError`("reading 'split'") → 정상(total 1).
    - A39 — 40,000자 위임: `"spawn ENAMETOOLONG"`(이력 0줄) → 실제로 시작(가짜 grok이 인자를 받았다), 구조화된 오류 + 이력 1줄.
  - 함수 수준: A37 9/9 가림, A44 영어 토큰 작업 HIGH·"in 1 file" MEDIUM, A38 bare 레이아웃 삭제 1 → 0, A39 40,000자 인자
    `reject` → `spawnError`, A46 3e9 캡이 3초 자식을 끝까지 둠, A41 손자 사례 8.1초 → 2.07초·`timedOut: false`.
- **실제 grok 1회(구독, 1.0.41):** 9,134자 프롬프트, 유일한 지시는 맨 끝 → `--prompt-file`로 넘어가 grok-4.7-build가
  `PROMPTFILE_OK`로 정확히 답했다. 남은 `grok-prompt-*` 폴더 0. (그때 한도는 8,000자였다 — 지금 그 길이는 argv로 간다.
  잰 것은 grok이 파일을 프롬프트로 읽는다는 사실이다.)
- **정규식:** 재작성을 원본과 무작위 입력 20만 개(고유 115K~127K)로 차등 비교 — 불일치 0. 최악 입력(64K자) 최대 5.3초 →
  1ms 이하. 가림은 64K자 `eyJ-eyJ-…` 1.87초 → 1ms.
- **POSIX 그룹 kill(A48):** Linux 컨테이너(node:22-bookworm)에서 detached 없이 띄운 자식은 `ESRCH`로 살아남고, detached면
  SIGKILL로 죽는다.
- **bare 레이아웃(A38):** 실제 git 2.45에서 `gitdir: …/proj.bare/worktrees/<n>` — 옛 정규식 일치 0.

## 하지 않는 것

- **가림은 여전히 완화다.** 옛 가림에서도 새던 형태는 새로 막지 않았다 — 한 단어 이름의 짧은 값(`PASSWORD=hunter2`),
  공백·쉼표·따옴표가 든 값, 닫히지 않은 인용, 이스케이프된 JSON, `os.environ["X"] =`, `SSHPASS`·`APP_KEY`·
  `SECRET_KEY_BASE`·`SUPABASE_SERVICE_ROLE_KEY`·`SESSION_KEY`, docker의 `"auth":`, 공백이 섞인 passphrase, `Token`/`Bot`
  인증 스킴, Slack webhook 경로, `rk_live_`/`glpat-` 형태(적대 검토의 40형태 중 19가 옛 가림과 같이 샌다).
- **과잉 가림 몇은 절충으로 남겼다.** 환경 변수 이름 뒤의 산문(`Rotate DB_PASSWORD: it was exposed` → `it`),
  `RENDER_PASS=shadow`·`EOF_TOKEN=eof`·`DB_SECRET=db-credentials`, 숫자 섞인 경로·태그(`token=src/…/Button.v2.tsx`,
  `signingKey=release-2024`), 인용 없는 값 안의 `;` 뒤(`DB_PASSWORD=hunter2;DB_HOST=db`는 뒤까지 가린다 — 연결
  문자열의 `;`를 지키려고). 반대쪽 절충: 인용 없는 호출 모양 비밀(`P4ss(w0rd)`)은 코드로 읽혀 남는다.
- **win32의 손자 프로세스는 여전히 살아남을 수 있고, POSIX에서도 자기 그룹을 만든 손자는 그렇다** — 끝나는 것은
  호출이다(`docs/06` "플랫폼 지원").
- **Linux·macOS에서 grok의 `--prompt-file`, `--sandbox`와 긴 프롬프트의 조합은 재지 않았다** — 둘 다 전에는 시작조차
  못 하던 길이이므로 후퇴는 아니다(argv가 싣는 프롬프트는 전과 같은 `--single=`로 간다).
- **감사의 문서 항목은 이 릴리스 범위 밖이다** — `docs/09` §4 E. 이 릴리스가 바꾼 계약에 닿는 문서만 맞췄다.
- **SonarQube의 스타일 지적(인지 복잡도, 정규식 복잡도 등)은 고치지 않았다** — 결함이 아니다.

## 머지 전 검토

독립 검토자 셋(코드·문서·적대적 실측)이 `566ba73`을 읽고 쟀다. 지적은 전부 두 번째 방법으로 다시 잰 뒤에 고쳤다 —
옛 418c1e9와 같은 입력으로 대조, 검토자의 스크립트를 수정본에 그대로, Linux 컨테이너, 실제 git 2.54.

**이 릴리스의 수정이 만든 결함 — 머지 전에 잡았다.**
- **가림이 옛 가림보다 샜다.** 붙여 쓴 이름(`accesskey`·`privatekey`), 자리표시 모양의 실제 값(`$uperS3cret…`·`<…>`·
  `%…%`·`your-…`), 셸 기본값(`${PGPASS:-…}`), 접두사 뒤의 이름 붙은 키(`process.env.GITHUB_TOKEN`·`--GITHUB_TOKEN`),
  글자 뒤 따옴표(`x"password":`), 이름 붙은 키의 짧은 숫자(`XAI_API_KEY=12345`), `-` 바로 뒤의 JWT
  (`cookie=session-eyJ…`). 적대 검토의 대조 한 벌에서만 17가지였다.
- **가림이 다시 2차가 됐다.** 가리지 않은 값을 건너뛰지 않아 `pwd=${pwd=${…`가 64K자 268ms, 512K자 17.4초.
- **가림이 둘레를 가져갔다.** 닫는 괄호·백틱·마침표, 빈 값 다음 줄의 대입(`DB_PASSWORD= DB_HOST=localhost` → 뒤 줄이
  사라짐). 설정·타입·코드도 가렸다(`FIRST_PASS=enabled`, `MAX_OUTPUT_TOKEN=128000`, `DB_PASSWORD: SecretStr`,
  `z.string().min(32)`) — 산문 23행 중 21행.
- **긴 프롬프트:** 8,000자 한도가 argv로 충분한 프롬프트도 파일로 보냈다(Linux는 인자 하나에 약 128 KiB를 싣는다).
- **지문:** untracked 파일을 하나씩 전부 읽었다 — 20,000개에 win32 7.2~7.6초, Linux 8.4초, plan마다 두 번, timeout 밖.
  이름이 공백으로 끝나는 저장소 폴더(Linux)에서는 같은 크기 재작성 3/3을 놓쳤다(`--show-toplevel`을 `trim`).
- **라우팅:** `1,000 files`류를 대량으로 못 읽었고(무작위 차등 5,914 뒤집힘), `tokenizer`·`max tokens`·
  `design tokens`가 보안 HIGH가 됐다.
- **prune:** 기준 폴더가 심볼릭 링크 너머면 상대 gitdir가 없는 소유자를 가리켰다(실제 git 2.54) — 상태 확인이
  실패하면 살아 있는 트리를 고아로 지웠고, 실제 apply는 매번 실패했다.

**이 릴리스 전부터 있던 것 — 같은 약속 안이라 같이 고쳤다.**
- `s3 rm`을 되풀이한 과제가 2차(64K자 307ms, 256K자 5.0초) — A43과 같은 종류.
- 파일 서술자가 바닥나면 `spawn`이 파이프 없는 자식을 돌려주고 **서버 프로세스가 죽었다**(exit 1, `ulimit -n`으로 잼) —
  A39의 "시작 실패는 구조화된 오류".
- 이력 한 줄의 `ts`가 변환할 수 없는 객체면 두 대시보드가 죽었다 — A40의 "한 줄이 대시보드를 못 죽인다".

**테스트와 문서의 빈틈.** kill이 실패하는 캡(A41 유예)·빈 plan의 사용량과 세션에 테스트가 없었다. PEM 시간 테스트는 옛
코드에서도 통과했다(2,000개 47ms — 8,000개로 올리자 옛 코드 862ms). A38 테스트는 돌 때마다 임시 폴더를 남겼다. 문서는
임시 파일(SECURITY.md·원칙 #4), `/grok:plan`의 커밋 메시지, 실패 봉투의 `sessionId`·사용량, 파일 트리, 계약 §1의 버전과
재지 않은 범위, POSIX 손자 정리의 한계, unauth probe의 방법 줄과 CHANGELOG의 옛 판정을 고쳤다.

## Grok과 함께 한 것

- **구현:** A40·A43(라우팅·usage·semver)·A44·A47·A48은 Grok이 격리 worktree에서 구현했다 — 계약은 먼저 커밋한 실패
  테스트 22개였다. diff를 한 줄씩 검토하고 이 제품의 `grok_build_worktree apply`로 가져왔다. 손댄 것은 반복된 주석 셋을
  하나로 합치고, 지운 메모를 가리키던 probe 머리말을 다시 쓴 것뿐이다. 16턴, 15분 캡 안.
- **제안:** 가림 테스트 말뭉치 30행(비밀 15·산문 15)을 가림을 보지 않고 썼다 — 비밀 14행·산문 14행을 그대로 테스트에
  넣어 전부 통과했다. 나머지 둘: Slack webhook 경로는 새 형태라 범위 밖(위 "하지 않는 것"), URL 형식 문자열은 A6 규칙의
  의도된 선택이라 그 동작을 고정했다.
- **적대적 반증:** 새 가림 규칙을 사실로 주고 "틀리는 곳"을 물었다 — 20행을 실제 가림에 돌려 보니 추적이 모두 맞았다.
  같은 20행을 옛 가림에도 돌렸다: 18행은 거기서도 같은 기존 한계였고(그중 누출 2행 — passphrase, Azure `AccountKey` — 은
  새 규칙의 틀 안에서 닫을 수 있어 고쳤다), 이번 규칙이 새로 만든 것은 과잉 가림 2행뿐이었다(위).
- **분류 판정:** spawn 시나리오 10행, 소유자 파싱 10행, plan 필드 9행 — 29/29 CORRECT(준 사실 범위 안에서; 같은 동작을
  테스트가 실측으로 고정한다).
- **틀린 것:** 감사 때 Grok의 정규식 재작성 6개는 모두 JavaScript에 없는 소유 한정자(`\s*+`)라 컴파일조차 되지 않았다 —
  진단만 맞았다. 이번 구현 과제에는 그 금지를 명시했고, 지켜졌다.
- **놓친 것:** Grok의 적대 패스(20행)는 머지 전 검토가 찾은 가림 회귀를 보지 못했다 — 과제에 **새 규칙만** 줬기 때문이다.
  옛 규칙이 덮던 것을 잃었는지는 묻지 않았고, 그건 옛 가림과 같은 줄로 대조해야 보인다(검토자와 내가 했다).
